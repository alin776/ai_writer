### 问题2: **权重总和不为1** (严重度: 🔴 P0)

**位置**: `node_metadata.py` Line 210-243

**问题描述**:
虽然实现了`calculate_scenario_total_weight()`函数，但**没有验证总和是否为1**！

**测试结果**:
```python
# 运行 python node_metadata.py 会输出:
writing       : 0.50 (2 节点)  # ❌ 应该是1.00
planning      : 0.45 (2 节点)  # ❌ 应该是1.00
analysis      : 0.45 (2 节点)  # ❌ 应该是1.00
stuck         : 0.35 (2 节点)  # ❌ 应该是1.00
general       : 0.30 (2 节点)  # ❌ 应该是1.00
react         : 0.80 (4 节点)  # ❌ 应该是1.00 (且节点不存在)
planning_mode : 0.70 (4 节点)  # ❌ 应该是1.00 (且节点不存在)
```

**影响**:
- 进度百分比会严重不准确
- 用户看到的进度会在50%左右就停止

**修复建议**:
```python
def validate_weights() -> Dict[str, Any]:
    """验证权重配置"""
    errors = []

    # ✅ 新增：验证场景总权重
    for scenario in ["writing", "planning", "analysis", "stuck", "general"]:
        total_weight = calculate_scenario_total_weight(scenario)
        if abs(total_weight - 1.0) > 0.01:  # 允许0.01的误差
            errors.append(
                f"场景 {scenario} 的总权重 {total_weight:.2f} 不等于1.0"
            )

    return {"valid": len(errors) == 0, "errors": errors}
```

### 问题3: **集成方案不可行** (严重度: 🔴 P0)

**位置**: `PROGRESS_TRACKER_INTEGRATION.md` Line 69-96

**问题描述**:
集成方案中建议在`_handle_stream_event`中检测节点开始/结束的逻辑**完全错误**！

**错误代码**:
```python
# ❌ 错误的检测逻辑 (INTEGRATION.md Line 72-83)
is_node_end = any(
    hasattr(msg, "__class__") and msg.__class__.__name__ == "AIMessage"
    for msg in messages
)

if is_node_end:
    progress_tracker.end_node(node_name)
else:
    progress_tracker.start_node(node_name)
```

**为什么错误**:
1. LangGraph的`astream()`事件中**每个event都是节点完成后的状态**
2. 没有"节点开始"事件，只有"节点完成"事件
3. 检测AIMessage的逻辑会导致所有Agent节点被误判为"结束"

**修复建议**:
```python
# ✅ 正确的集成方式
async def _handle_stream_event(
    self,
    event: dict,
    on_progress: Optional[callable] = None,
    progress_tracker: Optional[ProgressTracker] = None
):
    if not event:
        return

    node_name = list(event.keys())[0]

    # ✅ 方案1: 简化为只记录节点完成
    if progress_tracker:
        progress_tracker.end_node(node_name)

    # ✅ 方案2: 使用状态机跟踪
    # if progress_tracker:
    #     if node_name not in progress_tracker.completed_nodes:
    #         progress_tracker.start_node(node_name)
    #     progress_tracker.end_node(node_name)
```

### 问题4: **性能问题 - 潜在内存泄漏** (严重度: 🟡 P1)

**位置**: `progress_tracker.py` Line 42-45

**问题描述**:
```python
self.completed_nodes: List[str] = []
self.node_start_times: Dict[str, float] = {}
self.node_durations: Dict[str, float] = {}
self.eta_history: deque = deque(maxlen=5)
```

**问题**:
- `completed_nodes`, `node_durations` 没有大小限制
- 在长对话中会无限增长
- `node_start_times`虽然在`end_node`中删除，但如果节点异常退出会泄漏

**修复建议**:
```python
# ✅ 方案1: 添加最大历史记录限制
self.completed_nodes = deque(maxlen=100)  # 最多保留100个节点历史
self.node_durations = {}  # 定期清理（超过100条）

# ✅ 方案2: reset()时清理所有历史
def reset(self):
    self.completed_nodes.clear()
    self.node_durations.clear()
    self.node_start_times.clear()  # ✅ 清理可能泄漏的start_times
```

#### 5.3 节点重复完成处理

**位置**: `progress_tracker.py` Line 88-89

**问题**:
如果同一个节点被多次调用`end_node()`，会被重复添加到`completed_nodes`

**当前代码**:
```python

    self.completed_nodes.append(node_name)
```

**问题**: 虽然有检查，但在并发情况下可能失效

**修复**:
```python
# ✅ 使用集合避免重复
self.completed_nodes_set = set()  # 初始化时添加

# end_node中:
if node_name not in self.completed_nodes_set:
    self.completed_nodes.append(node_name)
    self.completed_nodes_set.add(node_name)
```
