## ⏳ Phase 3.8: 消息清理策略 - 需求评估

### 当前实现分析

**现有代码** (`langgraph_agent.py:1886-1939`):
```python
# 当前阈值
if message_count > 8:  # 触发清理
    # 保留策略：
    # 1. 所有系统消息
    # 2. 最近1条用户消息
    # 3. 最近2对AI-Tool交互（最多4条）
    # 总共最多6条
```

**当前特点**:
- ✅ 智能成对保留（AI-Tool成对）
- ✅ 按原始顺序重组
- ✅ 压缩率日志
- ✅ 避免破坏对话连贯性

### Phase 3.8建议对比

| 方面 | 当前实现 | Phase 3.8建议 | 评估 |
|------|---------|--------------|------|
| 阈值 | 8条 | 15条 | ⚠️ 需评估 |
| 策略 | 固定保留6条 | 动态（small/medium/large）| ⚠️ 需评估 |
| 成对保留 | ✅ 已实现 | 智能成对保留 | ✅ 已有 |

### 深度分析

**问题1**: 阈值8条是否过低？

**分析**:
- 典型对话：1 system + 1 user + 2-3对交互 = 5-7条
- 触发清理时：message_count > 8，保留6条
- **结论**: ✅ **阈值合理**，在第2-3轮对话后触发

**问题2**: 是否需要动态策略？

**当前固定策略收益**:
- ✅ 简单明确，易于理解
- ✅ 保证对话连贯性
- ✅ 已经是智能成对保留

**动态策略复杂度**:
- ⚠️ 增加复杂度
- ⚠️ 难以预测行为
- ⚠️ 可能引入新问题

**结论**: ⏳ **当前实现已经足够好，动态策略收益有限**

### 建议

**建议1**: ✅ **保持当前实现**
- 当前实现已经是智能的
- 成对保留已实现
- 简单可靠

**建议2**: ⏳ **小幅优化（可选）**
- 将阈值提高到10-12（而非15）
- 保留策略改为3对交互（而非2对）
- 添加更多日志

**建议3**: ⏳ **监控先行**
- 添加清理统计监控
- 收集实际使用数据
- 基于数据决定是否优化
