# 重构总结 - 独立会话方案

**重构时间**: 2025-10-27
**问题**: 并发数据库会话冲突导致90%任务失败
**解决方案**: 每个并发任务使用独立的数据库会话

---

## 问题回顾

### Lock方案为什么失败?

**核心问题**: 多个并发协程共享同一个数据库会话

```python
# ❌ 错误的方案
class NovelAnalysisOrchestrator:
    def __init__(self, db: AsyncSession):
        self.db = db  # 所有并发任务共享这个会话!

# 5个并发任务都使用同一个会话
# → 当一个任务commit时,其他任务无法查询
# → SQLAlchemy错误: cannot perform operation: another operation is in progress
```

**测试结果**: 成功率10% (2/20章)

---

## 重构方案

### 核心思想: 独立会话

**每个并发任务创建自己的数据库会话,彻底避免冲突**

---

## 重构步骤

### 步骤1: 添加会话工厂函数

**文件**: `backend/app/core/database.py`

```python
async def create_db_session() -> AsyncSession:
    """
    创建独立的数据库会话(用于并发任务)

    使用方法:
    async with create_db_session() as session:
        # 使用session
        await session.commit()
    """
    return AsyncSessionLocal()
```

**作用**: 提供一个方便的函数来创建新会话

---

### 步骤2: 修改orchestrator并发逻辑

**文件**: `backend/app/services/ai/novel_analysis_orchestrator.py`

#### 修改前 ❌
```python
async def analyze_single_chapter(idx: int, chapter):
    # AI分析
    micro_result = await self.micro_service.analyze_chapter(...)

    # ❌ 使用共享会话
    await self.analysis_service.save_micro_result(...)
    await self.vector_service.store_micro_analysis_vector(...)
```

#### 修改后 ✅
```python
async def analyze_single_chapter(idx: int, chapter):
    async with create_db_session() as session:
        # 为这个任务创建独立的会话
        try:
            # AI分析
            micro_result = await self.micro_service.analyze_chapter(...)

            # ✅ 使用独立会话
            analysis_service = NovelAnalysisService(session)
            await analysis_service.save_micro_result(...)

            vector_service = VectorStoreService(session)
            await vector_service.store_micro_analysis_vector(...)

            return ('success', micro_result)

        except Exception as e:
            await session.rollback()
            return ('failed', {...})
```

**关键变化**:
1. 每个并发任务创建自己的`session`
2. 为这个会话创建独立的`service`实例
3. 使用`async with`确保会话正确关闭
4. 异常时自动rollback

---

### 步骤3: 移除Lock机制

**文件**: `backend/app/services/novel_analysis_service.py`

#### 移除类级别Lock
```python
# ❌ 移除
class NovelAnalysisService:
    _db_lock = asyncio.Lock()  # 不再需要!

# ✅ 修改后
class NovelAnalysisService:
    def __init__(self, db: AsyncSession):
        self.db = db  # 每个实例使用独立会话
```

#### 移除方法中的Lock
```python
# ❌ 移除
async def save_micro_result(...):
    async with self._db_lock:
        # ...

# ✅ 修改后
async def save_micro_result(...):
    try:
        # 直接操作,不需要Lock
        await self.db.commit()
    except Exception as e:
        await self.db.rollback()
        raise
```

**原因**: 每个任务使用独立会话,不存在冲突,不需要Lock!

## 工作原理对比

### 旧方案(共享会话) ❌

```
时间  协程1(session)      协程2(session)      协程3(session)     会话状态
T1    查询                                                        执行中
T2    commit开始          等待                                    提交中
T3    ↓                   尝试查询             等待               提交中
T4    ↓                   ❌ 错误!             等待               提交中
T5    commit完成          ❌                  尝试查询            空闲
T6                        ❌                  ❌ 错误!            错误
```

**问题**: 同一个session不能并发使用

---

### 新方案(独立会话) ✅

```
时间  协程1(session_1)    协程2(session_2)    协程3(session_3)
T1    查询                查询                查询
T2    commit开始          commit开始          commit开始
T3    commit完成 ✓        commit完成 ✓        commit完成 ✓
```

**优势**: 每个协程使用独立session,完全并发,无冲突!

## 技术细节

### 1. 会话生命周期管理

```python

    # 会话自动管理
    # - 创建: 进入with
    # - 使用: with代码块内
    # - 关闭: 退出with (自动commit或rollback)
```

### 2. 异常处理

```python
async with create_db_session() as session:
    try:
        await session.commit()
```

### 3. 进度更新仍使用主会话

## 经验教训

### 1. 理解问题本质很重要

**表面问题**: commit冲突
**本质问题**: 会话共享

如果只看表面,会用Lock去修,结果无效。

### 2. 遵循框架最佳实践

SQLAlchemy文档明确说:
> Session is not thread-safe or coroutine-safe

每个协程/线程应该使用独立会话。

### 3. 简单方案往往最好

- 复杂的Lock方案 → 失败
- 简单的独立会话 → 成功

### 4. 测试驱动很关键

通过测试发现Lock方案无效,避免了生产环境问题。
