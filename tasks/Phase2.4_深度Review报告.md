### 问题2: ReAct模式重复意图识别 ✅ 已修复

**问题描述** (用户发现):
ReAct模式存在**双重意图识别**,造成严重浪费:

```
chat_stream()
  └─> _classify_intent_async()  ← 第1次识别 (已优化但重复❌)
      └─> 选择Prompt模板
      └─> 将intent存入initial_state

  └─> LangGraph.astream()
      └─> intent_classifier节点
          └─> _classify_intent()  ← 第2次识别 (重复❌)
              └─> 路由到不同Agent
```

**根本原因**:
- `chat_stream`预先识别意图是为了选择Prompt模板
- 但LangGraph的第一个节点就是`intent_classifier`
- **两次识别完全重复,第一次没有实际作用**

**修复方案** (用户建议):
- ✅ **移除`chat_stream`中的预先意图识别**
- ✅ 使用默认的writing_agent模板
- ✅ 让LangGraph的intent_classifier节点自动识别
- ✅ initial_state的intent设为None

**修复代码**:
```python
# 优化前: 预先识别意图 (重复!)
intent_data = await self._classify_intent_async(message)
detected_intent = intent_data.get("intent", "writing")
template_name = self._select_template(detected_intent)
system_prompt = self.prompt_manager.render(template_name, ...)
initial_state = {"intent": detected_intent, ...}

# 优化后: 移除重复识别
system_prompt = self.prompt_manager.render("writing_agent", ...)
initial_state = {"intent": None, ...}  # LangGraph会自动识别
```

**收益**:
- ✅ 完全消除重复识别
- ✅ 代码更简洁清晰
- ✅ 性能提升(虽然第二次已优化,但避免了重复)

## 🔬 深度探索发现

### 1. 架构设计洞察

**发现**: ReAct模式和Planning模式使用了不同的执行路径
- ReAct: 预先意图识别 → LangGraph流式执行
- Planning: 直接进入Planning流程,无意图识别

**原因**: Planning模式本身就是"规划+执行",不需要意图识别

### 2. 重复识别问题

**发现**: ReAct模式可能存在**双重意图识别**
- chat_stream调用`_classify_intent_async`
- LangGraph内部调用`_classify_intent`

**建议**: 可以考虑优化,去除其中一个(但需要仔细测试)

### 3. 意图类型不统一

**发现**: 两套意图类型系统
- LangGraph: 5种意图
- chat_stream: 4种意图

**影响**: 需要映射转换,增加复杂度

**建议**: 未来统一意图类型定义
