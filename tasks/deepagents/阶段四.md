### ⚠️ chapters 表外键依赖处理（DROP 前必做）

`chapters` 表被 **8 个保留中的表** 通过外键引用，直接 DROP 会导致**数据丢失或迁移失败**：

| 保留的表 | FK 列 | ondelete | 风险 | 处理方式 |
|---|---|---|---|---|
| `agent_session` | `chapter_id` | SET NULL | 低（值变 NULL） | 先 ALTER DROP COLUMN（阶段二已规划去 chapter_id） |
| `ai_call_log` | `chapter_id` | SET NULL | 低（值变 NULL） | ALTER DROP CONSTRAINT，保留列作历史记录 |
| `bookshelf` | `last_read_chapter_id` | SET NULL | 低（值变 NULL） | ALTER DROP CONSTRAINT |
| `chapter_comment` | `chapter_id` | **CASCADE** | ⚠️ **高：所有评论被删** | 评估是否保留表；如保留需先 DROP CONSTRAINT |
| `chapter_word_stat` | `chapter_id` | **CASCADE** | ⚠️ **高：统计数据被删** | 重构后由文件系统实时计算，可接受删除 |
| `evaluation_record` | `chapter_id` | SET NULL | 低（值变 NULL） | ALTER DROP CONSTRAINT |
| `knowledge_item` | `chapter_id` | 无指定 | ⚠️ **迁移报错** | 必须先 ALTER DROP CONSTRAINT |
| `relationship` | `start/end_chapter_id` | 无指定 | ⚠️ **迁移报错** | 必须先 ALTER DROP CONSTRAINT |
| `review_task` | `chapter_id` | 无指定 | ⚠️ **迁移报错** | 必须先 ALTER DROP CONSTRAINT |
| `timeline_event` | `chapter_id` | SET NULL | 低（值变 NULL） | ALTER DROP CONSTRAINT |

**关键决策**：

| 表 | 决策 | 理由 |
|---|---|---|
| `chapter_comment` | 一起 DROP | 评论绑定在 DB 章节 UUID 上，文件系统章节用序号，无法映射 |
| `chapter_word_stat` | 一起 DROP | 重构后字数由文件系统实时计算，不再需要此表 |
| 其余 6 张表 | ALTER DROP CONSTRAINT/COLUMN | 保留表，去掉 FK 约束 |

**Alembic 迁移脚本模板**（在 DROP 废弃表之前执行）：

```python
def upgrade():
    # === 第 1 步：处理保留表的 FK 约束 ===

    # agent_session: 去掉 chapter_id 列（阶段二已规划）
    op.drop_constraint('agent_sessions_chapter_id_fkey', 'agent_sessions', type_='foreignkey')
    op.drop_column('agent_sessions', 'chapter_id')

    # 其他保留表：去掉 FK 约束，保留列（历史数据）
    for table, constraint in [
        ('ai_call_logs', 'ai_call_logs_chapter_id_fkey'),
        ('bookshelves', 'bookshelves_last_read_chapter_id_fkey'),
        ('evaluation_records', 'evaluation_records_chapter_id_fkey'),
        ('knowledge_items', 'knowledge_items_chapter_id_fkey'),
        ('relationships', 'relationships_start_chapter_id_fkey'),
        ('relationships', 'relationships_end_chapter_id_fkey'),
        ('review_tasks', 'review_tasks_chapter_id_fkey'),
        ('timeline_events', 'timeline_events_chapter_id_fkey'),
    ]:
        op.drop_constraint(constraint, table, type_='foreignkey')

    # === 第 2 步：DROP 级联删除的附属表（评论、字数统计）===
    op.drop_table('chapter_comments')
    op.drop_table('chapter_word_stats')

    # === 第 3 步：DROP 7 张核心废弃表 ===
    op.drop_table('chapter_content_indexes')
    op.drop_table('chapter_revisions')
    op.drop_table('novel_chapter_vectors')
    op.drop_table('novel_analysis_vectors')
    op.drop_table('chapter_versions')
    op.drop_table('chapter_histories')
    op.drop_table('chapters')  # 最后删主表

    # === 第 4 步：清理 pgvector 扩展 ===
    op.execute('DROP EXTENSION IF EXISTS vector')
```

## 三-B、任务 4.0（前置）— 数据迁移：DB → 文件系统

> **时机**：在阶段三完成（前端切换到文件系统 API）之后、阶段四删除（DROP 表）之前执行。
> 这是 Strangler Fig Pattern 的关键中间步——"搬家"。

### 迁移范围

| 数据源 | 目标 | 说明 |
|---|---|---|
| `chapters` 表 `content` 列 | `chapters/XX.md` 文件 | 核心迁移 |
| `chapters` 表 `title` / `status` | `.md` 文件 frontmatter | 元数据迁移 |
| `chapters` 表 `order` | 文件名序号（01, 02, ...） | 排序迁移 |

### 迁移脚本核心逻辑

```python
# scripts/migrate_db_to_filesystem.py

async def migrate_work(work_id: str, db: AsyncSession):
    """将一部作品的章节从 DB 迁移到文件系统"""
    work = await db.get(Work, work_id)
    root_dir = Path(f"users/{work.user_id}/works/{work.title}")
    root_dir.mkdir(parents=True, exist_ok=True)

    # 按 order 排序查询所有章节
    chapters = await db.execute(
        select(Chapter)
        .where(Chapter.work_id == work_id)
        .order_by(Chapter.order)
    )

    for i, chapter in enumerate(chapters.scalars(), start=1):
        # 组装 frontmatter + 正文
        md_content = f"""---
title: {chapter.title}
status: {chapter.status or 'draft'}
---

{chapter.content or ''}"""

        # 写入文件
        file_path = root_dir / "chapters" / f"{i:02d}.md"
        file_path.parent.mkdir(parents=True, exist_ok=True)
        file_path.write_text(md_content, encoding="utf-8")

    print(f"[OK] {work.title}: {i} 章已迁移")
```

### 迁移验证

```python
# 迁移后验证：文件数 == DB 章节数，内容一致
async def verify_migration(work_id, db):
    db_count = await db.scalar(
        select(func.count()).where(Chapter.work_id == work_id)
    )
    file_count = len(list((root_dir / "chapters").glob("*.md")))
    assert db_count == file_count, f"数量不匹配: DB={db_count}, 文件={file_count}"
```

### 迁移策略

| 策略 | 说明 |
|---|---|
| 幂等 | 脚本可重复执行（跳过已存在的文件） |
| 批次 | 按作品粒度迁移，一次失败不影响其他作品 |
| 双写期 | 迁移后保留 DB 数据，直到阶段四 DROP 表 |
| 回滚 | 迁移期间 DB 仍是主数据源，删文件即可回滚 |
