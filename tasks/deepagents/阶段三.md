# 阶段三开发文档：前端改造（UI）

## Context

阶段二搭建后端核心 Agent，阶段三对接前端。目标是用极简方案替换现有重装 UI，匹配 DeepAgents 的 Markdown 文件系统架构。

---

## 一、任务 3.1 — 替换编辑器：Tiptap → Milkdown

### 为什么换

核心矛盾：Tiptap 内部模型是 HTML/JSON，DeepAgents 文件系统全是 Markdown。

```
现在的数据流（需要转换层）：
  文件系统 .md → 解析成 HTML → Tiptap 渲染 → 导出 HTML → 转回 .md → 写文件

Milkdown 的数据流（零转换）：
  文件系统 .md → Milkdown 直接渲染 → 导出 md string → 直接写文件
```

现有 NovelEditor 有 2,397 行 + 18 个 Tiptap 包 + 5 个自定义扩展，大部分功能重构后不需要。与其改造，不如用 Milkdown 从零搭极简编辑器。

### 砍什么、留什么

| 现有功能 | 行数 | 决定 | 理由 |
|---|---|---|---|
| 纯文本 + 标题编辑 | — | ✅ 保留 | 写小说的核心 |
| 自动保存（3s debounce） | ~50 行 | ✅ 保留逻辑 | 用户体验必须 |
| localStorage 备份 | ~30 行 | ✅ 保留逻辑 | 防丢失 |
| 字数统计 | ~20 行 | ✅ 保留 | 写作刚需 |
| **Diff 视图**（红删绿增） | 新建 | ✅ 核心新功能 | Agent edit_file 审批用 |
| EditorToolbar（6 个图标） | 187 行 | ⚠️ 极简化 | Milkdown crepe 预设自带 |
| BubbleMenu（选中浮动菜单） | 181 行 | ❌ 砍 | 小说主要纯文字 |
| AIMenu（AI 操作菜单） | 636 行 | ❌ 砍 | Agent 在对话面板交互 |
| AIAutoComplete（流式补全） | 408 行 | ❌ 砍 | 第一版不做 |
| AIRevisionMark（3 个自定义 Mark） | 154 行 | ❌ 砍 | 被 edit_file diff 视图替代 |
| AIRevisionBar（接受/拒绝浮窗） | 103 行 | ❌ 砍 | 审批在 diff 视图里做 |
| SlashCommand（/ 命令） | 140 行 | ❌ 砍 | 写小说不需要 |
| UniqueID（节点唯一 ID） | 338 行 | ❌ 砍 | 不再需要 ProseMirror 级定位 |
| DragHandle（拖拽排序） | 外部包 | ❌ 砍 | 非必须 |
| AIContinueDrawer（续写抽屉） | 661 行 | ❌ 砍 | Agent 对话替代 |

砍掉约 2,800 行代码 + 12 个 Tiptap 包，新编辑器预计 300~500 行。

### Milkdown 技术方案

Milkdown 是基于 ProseMirror 的 Markdown 编辑器框架，内部模型就是 Markdown，所见即所得。

#### 需要的包

```json
{
  "@milkdown/kit": "^7.x",
  "@milkdown/react": "^7.x",
  "@milkdown/crepe": "^7.x"
}
```

对比现有 18 个 `@tiptap/*` 包，只需 3 个包。

#### 数据流

```
加载：
  GET /api/works/{id}/chapters/01
    → { content: "月光穿过窗帘..." }    ← 纯 md string
    → Milkdown editor.create(content)   ← 直接渲染

保存：
  editor.getMarkdown()                  ← 导出 md string
    → PUT /api/works/{id}/chapters/01
    → { content: "编辑后的内容..." }    ← 直接写文件

零转换，md string 全程透传。
```

#### Diff 视图模式

编辑器支持两种模式切换：

```
普通模式（日常编辑）：
  ┌─────────────────────────┐
  │ 月光穿过窗帘的缝隙...    │  ← 正常 WYSIWYG 编辑
  └─────────────────────────┘

Diff 模式（点击变更卡片后）：
  ┌─────────────────────────┐
  │ - 他望着远方，心中一片平静。│  ← 红色删除
  │ + 他望着远方，指尖不自觉地  │  ← 绿色新增
  │ + 摩挲着那枚玉佩...       │
  │                          │
  │   [Accept]  [Reject]     │
  └─────────────────────────┘
```

Diff 模式不需要 Milkdown 渲染，直接用现有的 `DiffViewer.tsx`（77 行，基于 diff-match-patch）。编辑器区域在两种模式之间切换显示。

### 现有可复用的组件

| 组件 | 行数 | 复用方式 |
|---|---|---|
| `DiffViewer.tsx` | 77 行 | ✅ 直接复用（只关心 old/new 字符串） |
| 自动保存逻辑 | ~50 行 | ✅ 提取复用（debounce + localStorage） |
| `editor-styles.css` | 897 行 | 🔄 大幅精简（Milkdown 自带样式） |

### 整体对比

| | 现在（Tiptap） | 重构后（Milkdown） |
|---|---|---|
| 编辑器代码 | 2,397 行 | ~300-500 行 |
| npm 包数量 | 18 个 @tiptap/* | 3 个 @milkdown/* |
| 内部模型 | HTML/JSON | Markdown |
| 数据转换 | md ↔ HTML 互转 | 零转换 |
| 自定义扩展 | 5 个 | 0 个 |
| Diff 展示 | 自定义 ProseMirror Mark | DiffViewer 组件（已有） |
| CSS 样式 | 897 + 988 行 | ~200 行（crepe 预设自带） |

## 二、任务 3.2 — 章节目录数据源切换

### 是什么

左侧章节目录的数据来源从 DB API 改为文件系统 API。UI 样式基本不动，只换数据源。

### 数据源变化

```
现在：
  GET /chapters/work/{workId}
    → SELECT * FROM chapters WHERE work_id = ?
    → [{ id: "uuid", title: "黎明", wordCount: 2500, order: 0, ... }]

重构后：
  GET /api/works/{id}/chapters
    → ls chapters/ + 解析每个文件的 frontmatter
    → [{ number: "01", title: "黎明", wordCount: 2500, status: "draft" }]
```

### Chapter 类型变化

```typescript
// 现在（DB 驱动，20+ 字段）
interface Chapter {
  id: string;           // UUID
  workId: string;
  title: string;
  content: string;
  summary?: string;
  wordCount: number;
  viewCount: number;
  isPublished: boolean;
  order: number;        // 排序字段
  publishedAt: string;
  createdAt: string;
  updatedAt: string;
  status?: string;
}

// 重构后（文件驱动，6 个字段）
interface Chapter {
  number: string;       // 文件名序号 "01" "02"（即排序，即 ID）
  title: string;        // frontmatter 的 title
  status: string;       // frontmatter 的 status
  wordCount: number;    // 正文字数（实时计算）
  content?: string;     // 正文（列表不需要，打开时才加载）
}
```

从 20+ 字段精简到 6 个。`number` 同时充当 ID、排序、文件名三个角色。

### 交互变化

| 交互 | 现在 | 重构后 | 变化 |
|---|---|---|---|
| 点击打开 | `GET /chapters/{uuid}` | `GET /api/works/{id}/chapters/01` | 改 URL |
| 创建章节 | `POST /chapters` | `POST /api/works/{id}/chapters` | 改 URL，自动分配序号 |
| 重命名 | `PUT /chapters/{uuid}` 改 title | `PUT /api/works/{id}/chapters/01` 改 frontmatter | 改 URL |
| 删除 | `DELETE /chapters/{uuid}` | `DELETE /api/works/{id}/chapters/01` | 改 URL |
| 拖拽排序 | `POST /chapters/reorder` 改 order | 文件重命名（交换文件名） | 逻辑变化 |
| 显示标题 | `chapter.title` | `chapter.title`（从 frontmatter） | 不变 |
| 显示字数 | `chapter.wordCount` | `chapter.wordCount`（实时计算） | 不变 |

大部分交互只是改 API URL，显示逻辑完全不变。

### 拖拽排序的处理

文件系统下排序靠文件名，交换顺序需要重命名文件：

```
用户把第 3 章拖到第 1 章前面：

API：POST /api/works/{id}/chapters/reorder
Body: { from: "03", to: "01" }

后端：
  01.md → _tmp_01.md
  02.md → _tmp_02.md
  03.md → 01.md        ← 原第 3 章变第 1 章
  _tmp_01.md → 02.md   ← 原第 1 章变第 2 章
  _tmp_02.md → 03.md   ← 原第 2 章变第 3 章
```

逻辑在后端 API 里，前端只管调接口。

### 改动范围

| 文件 | 改动 | 大小 |
|---|---|---|
| `DataService.ts` | 章节方法改 URL + 响应格式 | 小 |
| `WorkDetailView/index.tsx` | `chapter.id` → `chapter.number` | 小 |
| `types/index.ts` | Chapter 接口精简 | 小 |
| `ChapterTree.tsx` | 字段名适配 | 小 |

UI 样式零改动。

## 三、任务 3.3 — 批量审批 UI

### 核心变化

从逐次审批（每个写操作弹窗）简化为批量审批（Agent 跑完后统一审批）。

### 砍什么、留什么

| 现有组件 | 决定 | 理由 |
|---|---|---|
| `DiffViewer.tsx`（77 行） | ✅ 直接复用 | 核心：红删绿增渲染 |
| `ExecutionFlow/index.tsx` | 🔄 大幅简化 | 保留容器概念，砍掉复杂 FlowItem 类型 |
| `AgentEditConfirmDialog.tsx` | ❌ 砍 | 弹窗逐个审批 → 批量审批替代 |
| `RevisionCard.tsx` | ❌ 砍 | 5 种类型 + 多版本 → 简单 FileChangeCard 替代 |
| `OperateCard.tsx` | ❌ 砍 | 3 阶段操作轨迹，过度设计 |
| `StepCard.tsx` | ❌ 砍 | 知识调取展示，DeepAgents 内部处理 |
| `useAgentChat.ts`（1,652 行） | 🔄 大幅简化 | SSE 从自研事件改为翻译框架事件，预计缩减至 ~300 行 |

### 新的 UI 组件（4 个）

#### 1. TextBlock — LLM 文字输出（流式）

Agent 的自然语言输出，ReAct 循环中 LLM 在工具调用之间产生的解释性文字：

```
我会在第三章结尾加入一个关于玉佩的细节描写
作为伏笔，然后在第七章揭开。
```

- 来源：`on_llm_stream` token 事件
- 流式渲染（逐字出现）
- 支持 Markdown 格式

#### 2. EventLine — 操作事件行

一个图标 + 一行文字，无交互：

```
📖 Read outline.md              ✓
🔍 Grep "李云飞"                 ✓
📋 WriteTodo 3 steps
```

#### 3. FileChangeCard — 文件变更卡片

可点击，点击后编辑器切到 diff 视图：

```
📄 chapters/03.md   +10 -1   ✓ ×
```

- 文件图标 + 文件名 + `+N -M` 统计 + ✓ × 快捷按钮
- 点击 → 编辑器切到 diff 视图（复用 DiffViewer）
- ✓ → 单个接受（flush 该操作）
- × → 单个拒绝（移除该操作）

#### 4. BatchActions — 批量操作栏

Agent 执行结束后出现：

```
[Accept All]  [Reject All]
```

### 四种组件的来源事件

| 组件 | 渲染什么 | 来源事件 |
|---|---|---|
| TextBlock | LLM 自然语言输出（流式） | `on_llm_stream` token |
| EventLine | 工具操作一行文字 | `on_tool_start/end`（非写操作） |
| FileChangeCard | 文件变更卡片 | `on_tool_start/end`（write/edit） |
| BatchActions | Accept All / Reject All | Agent 结束 |

### ReAct 循环与渲染的对应关系

```
ReAct 循环：
  LLM 输出文字（思考 + 解释）  →  TextBlock
  LLM 发起工具调用            →  EventLine / FileChangeCard
  工具返回结果                →  （不显示）
  LLM 输出更多文字            →  TextBlock
  LLM 发起下一个工具调用       →  EventLine / FileChangeCard
  ...重复
```

### 对话面板完整渲染示例

```
用户消息："在第三章埋伏笔，第七章揭开"
─────────────────────────────────
Agent:
  📖 Read outline.md              ✓     ← EventLine
  📖 Read chapters/03.md          ✓     ← EventLine
  📖 Read chapters/07.md          ✓     ← EventLine
  📖 Read characters.md           ✓     ← EventLine

  我会在第三章结尾加入一个关于玉佩的      ← TextBlock（LLM 文字输出）
  细节描写作为伏笔，然后在第七章揭开。

  📄 chapters/03.md  +10 -1      ✓ ×   ← FileChangeCard

  接下来处理第七章，让主角再次看到         ← TextBlock
  玉佩时回忆起第三章的场景：

  📄 chapters/07.md  +8  -1      ✓ ×   ← FileChangeCard

  已完成，两处伏笔已埋设。               ← TextBlock

  [Accept All]  [Reject All]       ← BatchActions
─────────────────────────────────
```

### 编辑器 Diff 视图联动

点击 FileChangeCard → 编辑器切换到 diff 模式：

```
┌──────────┬──────────────────┬──────────────────────────┐
│  左侧    │    中间 对话面板   │    右侧 编辑器            │
│  章节目录 │                  │                          │
│          │  📖 Read ...     │  chapters/03.md (diff)   │
│          │  📄 03.md +10 -1 │                          │
│          │  📄 07.md +8 -1  │  - 他望着远方，心中一片平静。│
│          │                  │  + 他望着远方，指尖不自觉地  │
│          │ [Accept All]     │  + 摩挲着那枚玉佩...       │
│          │ [Reject All]     │                          │
│          │                  │     [Accept] [Reject]     │
└──────────┴──────────────────┴──────────────────────────┘
```

数据流：
1. 用户点击 FileChangeCard
2. 从 `GET /agent/changes/{id}` 拿到 old/new 内容
3. 编辑器区域渲染 `DiffViewer(original=old, modified=new)`
4. 用户点 Accept/Reject → 调审批 API → 编辑器切回普通模式

### 自定义事件简化

```
现在（6 种 CustomEvent）：
  agent-chapter-preview / agent-chapter-revert / agent-chapter-confirm
  agent-operations-applied / agent-operations-rollback / agent-jump-revision

重构后（2 种）：
  agent-show-diff       ← 点击卡片，编辑器切到 diff 视图
  agent-changes-applied ← Accept 后，编辑器刷新内容
```

不再需要乐观更新——写操作都在缓冲区，审批前文件没变。
