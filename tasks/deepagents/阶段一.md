## 一、Agent 创建 — `create_deep_agent()`

### 真实 API

```python
from deepagents import create_deep_agent
from deepagents.backends import FilesystemBackend

agent = create_deep_agent(
    model="openai:gpt-4o",                    # 或其他 LLM
    system_prompt="你是一位专业的小说写作助手...",  # 自定义 prompt，置于框架内置 base_prompt 之前（先自定义，后框架指南）
    backend=FilesystemBackend(                 # 文件系统后端
        root_dir="users/{user_id}/works/{work_name}",
        virtual_mode=True,                     # 安全：禁止路径穿越
        max_file_size_mb=20,
    ),
    tools=[semantic_search_tool],              # 自定义工具（RAG 语义搜索）
    interrupt_on={                             # HITL 配置（按工具粒度）
        "write_file": True,
        "edit_file": True,
    },
    checkpointer=MemorySaver(),                # 状态持久化（interrupt/resume 必需）
)
```

**返回值**：`CompiledStateGraph`（LangGraph 编译后的状态机），用 `.invoke()` / `.stream()` 执行。

### 关键参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `model` | `str \| BaseChatModel` | LLM 模型 |
| `system_prompt` | `str \| SystemMessage` | 自定义提示词，**置于**内置 base_prompt **之前**（先自定义，后框架指南） |
| `backend` | `BackendProtocol` | 文件系统后端 |
| `tools` | `list[BaseTool \| Callable]` | 自定义工具列表 |
| `interrupt_on` | `dict[str, bool]` | 哪些工具需要人工审批 |
| `checkpointer` | `Checkpointer` | 状态持久化（MemorySaver / AsyncRedisSaver） |
| `middleware` | `Sequence[AgentMiddleware]` | 中间件栈（通常用默认） |
| `subagents` | `list[SubAgent]` | 子 Agent 定义 |

### 执行方式

```python
# 同步执行
result = agent.invoke(
    {"messages": [{"role": "user", "content": "续写第三章"}]},
    config={"configurable": {"thread_id": "xxx"}}
)

# 流式执行
for chunk in agent.stream(
    {"messages": [...]},
    config=config,
    stream_mode="updates"  # 可选: values / updates / messages / custom / debug
):
    print(chunk)

# 异步流式
async for event in agent.astream_events({"messages": [...]}, config=config):
    print(event)
```

## 二、FilesystemBackend — 文件系统后端

### 真实 API

```python
from deepagents.backends import FilesystemBackend

backend = FilesystemBackend(
    root_dir="/path/to/workspace",  # 工作目录根路径
    virtual_mode=True,              # 虚拟路径模式（安全隔离）
    max_file_size_mb=10,            # grep 扫描的文件大小上限
)
```

### 三个参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `root_dir` | 当前目录 | Agent 的工作根目录 |
| `virtual_mode` | `False` | `True` 时所有路径锚定在 root_dir，阻止 `..` 和 `~` 穿越 |
| `max_file_size_mb` | `10` | grep 跳过超过此大小的文件 |

### Shell 禁用机制

`FilesystemBackend` **不实现** `SandboxBackendProtocol`，框架检测到后**不创建** `execute` 工具。Agent 只能看到 6 个文件工具 + Planning 工具。零配置，天然安全。

```python
# 框架内部判断逻辑
def _supports_execution(backend):
    if isinstance(backend, CompositeBackend):
        return isinstance(backend.default, SandboxBackendProtocol)
    return isinstance(backend, SandboxBackendProtocol)
```

### 对写作场景的映射

我们将 `root_dir` 设在 Work 级别：

```
root_dir = "users/{user_id}/works/{work_name}"

Agent 看到的目录结构：
/
├── outline.md
├── worldview.md
├── characters.md
├── chapters/
│   ├── 01.md
│   └── 02.md
└── notes/
```

`virtual_mode=True` 确保 Agent 无法访问其他用户/作品的文件。

## 三、6 个文件系统工具 — 完整行为

### 3.1 read_file

```python
read_file(file_path: str, offset: int = 0, limit: int = 2000) -> str
```

| 行为 | 说明 |
|---|---|
| 分页 | `offset` 起始行（0-indexed），`limit` 最大行数 |
| 行号 | 输出带行号，从 `offset + 1` 开始 |
| 图片 | 支持 png/jpg/gif/webp，转 base64 返回 |
| 安全 | `O_RDONLY \| O_NOFOLLOW`，防符号链接攻击 |

### 3.2 write_file

```python
write_file(file_path: str, content: str) -> str
```

| 行为 | 说明 |
|---|---|
| ⚠️ **文件已存在时报错** | 返回 `"Cannot write to {path} because it already exists. Read and then make an edit."` |
| 自动创建父目录 | `parents=True, exist_ok=True` |
| 用途 | **仅用于创建新文件**（如新章节 `chapters/03.md`） |

**对写作场景的影响**：Agent 修改已有章节**必须用 `edit_file`**，不能用 `write_file` 覆盖。这符合我们的设计 —— `edit_file` 天然提供 old/new diff 数据。

### 3.3 edit_file（最重要）

```python
edit_file(file_path: str, old_string: str, new_string: str, replace_all: bool = False) -> str
```

| 行为 | 说明 |
|---|---|
| 匹配方式 | **字面字符串匹配**（不是正则） |
| `replace_all=False`（默认） | `old_string` 必须在文件中**恰好出现 1 次**，否则报错 |
| `replace_all=True` | 替换所有出现的位置 |
| `old_string` 找不到 | 返回错误信息 |
| 返回值 | 包含 `occurrences`（替换次数） |

**对写作场景的影响**：

- 续写章节：`edit_file("chapters/03.md", "现有结尾段落", "现有结尾段落\n\n新增内容...")`
- 段落改写：`edit_file("chapters/03.md", "要替换的段落", "改写后的段落")`
- 埋伏笔：`edit_file("chapters/03.md", "某段原文", "加了伏笔的新版")`
- **红删绿增来源**：`old_string` = 红色删除，`new_string` = 绿色新增

### 3.4 ls

```python
ls(path: str) -> str
```

| 行为 | 说明 |
|---|---|
| 非递归 | 只列出直接子项 |
| 返回信息 | 路径、是否目录、文件大小、修改时间 |
| 目录标识 | 目录路径末尾加 `/` |
| 排序 | 按路径排序 |

### 3.5 glob

```python
glob(pattern: str, path: str = "/") -> str
```

| 行为 | 说明 |
|---|---|
| 模式语法 | `*`（单层）、`**`（递归）、`?`（单字符） |
| 示例 | `chapters/*.md`、`**/*.md` |
| 只返回文件 | 不返回目录 |

### 3.6 grep

Agent 看到的工具签名（框架工具层包装后）：

```python
grep(pattern: str, path: str = None, glob: str = None, output_mode: str = "files_with_matches") -> str
```

Backend 实际方法签名（实现 BufferedFilesystemBackend 时关注这个）：

```python
# FilesystemBackend.grep_raw() — 无 output_mode 参数
grep_raw(pattern: str, path: str = None, glob: str = None) -> list[GrepMatch] | str
```

> **注意**：`output_mode` 是框架在工具层包装时添加的参数，不在 Backend 方法中。实现 BufferedFilesystemBackend 时**不需要重写 `grep_raw`**（grep 是只读操作，直接透传即可）。

| 行为 | 说明 |
|---|---|
| 匹配方式 | **字面字符串**（不是正则），使用 ripgrep `-F` |
| output_mode（工具层） | `files_with_matches`（默认，只返回文件名）/ `content`（返回匹配行+上下文）/ `count`（计数） |
| 底层实现 | 优先 ripgrep，不可用时退回 Python `re.escape()` |

## 四、HITL 机制 — interrupt_on

### 内置行为（逐个中断）

```python
agent = create_deep_agent(
    interrupt_on={"write_file": True, "edit_file": True},
    checkpointer=MemorySaver()
)

config = {"configurable": {"thread_id": str(uuid.uuid4())}}

# 执行到 write_file 时中断
result = agent.invoke({"messages": [...]}, config=config)

if result.get("__interrupt__"):
    # 获取中断信息
    action_requests = result["__interrupt__"][0].value["action_requests"]

    # 恢复（三种决策）
    from langgraph.types import Command
    result = agent.invoke(
        Command(resume={"decisions": [
            {"type": "approve"}      # 批准执行
            # {"type": "edit", ...}  # 修改后执行
            # {"type": "reject", "reason": "..."}  # 拒绝
        ]}),
        config=config  # 同一个 thread_id
    )
```

### 与我们需求的冲突

| | 框架内置 HITL | 我们的需求 |
|---|---|---|
| 中断时机 | **每个** write_file/edit_file 调用时中断 | Agent **跑完后**统一审批 |
| 审批粒度 | 一次审批一个操作 | 一次审批一批操作（可能跨多个文件） |
| Agent 状态 | 中断后暂停，等审批才继续 | Agent 全程不中断，自主跑完 |

### 解决方案：BufferedFilesystemBackend

**不用框架内置的 `interrupt_on`**，而是自己写一个缓冲后端：

```python
class BufferedFilesystemBackend(FilesystemBackend):
    """写操作缓冲，读操作透传"""

    def __init__(self, root_dir, **kwargs):
        super().__init__(root_dir, **kwargs)
        self.write_buffer = []  # 缓冲区

    def write(self, file_path, content):
        # 不落盘，存缓冲区
        self.write_buffer.append({
            "type": "write",
            "file_path": file_path,
            "content": content,
        })
        return WriteResult(error=None, path=file_path)

    def edit(self, file_path, old_string, new_string, replace_all=False):
        # 不落盘，存缓冲区
        self.write_buffer.append({
            "type": "edit",
            "file_path": file_path,
            "old_string": old_string,
            "new_string": new_string,
            "replace_all": replace_all,
        })
        return EditResult(error=None, path=file_path, occurrences=1)

    def read(self, file_path, offset=0, limit=2000):
        # 读操作检查缓冲区（Agent 可能先写再读）
        # 如果缓冲区有该文件的写入，返回缓冲内容
        # 否则透传到真实文件系统
        ...

    def flush(self):
        """审批通过后，将缓冲区全部写入文件系统"""
        for op in self.write_buffer:
            if op["type"] == "write":
                super().write(op["file_path"], op["content"])
            elif op["type"] == "edit":
                super().edit(op["file_path"], op["old_string"], op["new_string"], op["replace_all"])
        self.write_buffer.clear()

    def discard(self):
        """审批拒绝，丢弃缓冲区"""
        self.write_buffer.clear()

    def get_changes(self):
        """返回所有待审批的改动"""
        return self.write_buffer.copy()
```

**关键**：`read()` 需要考虑"Agent 先 write 了一个文件，后面又 read 它"的情况，要从缓冲区返回。

### 默认栈顺序

```

FilesystemMiddleware      → 6 个文件工具 + 大输出自动存文件
```

## 十一、目录初始化策略

### 决策：只建根目录

创建作品时**只创建根目录**：`users/{user_id}/works/{work_name}/`

其余文件全部由 Agent 按需通过 `write_file` 创建（`write_file` 自动创建父目录）。

**不预创建** outline.md / characters.md / worldview.md / chapters/ / notes/

原因：
- `write_file` 对已存在的文件报错 → 预创建空文件反而妨碍 Agent
- `write_file` 自动创建父目录 → Agent 写 `chapters/01.md` 时 `chapters/` 自动出现
- `ls` 对不存在的目录返回空列表 → 不会报错

**前提**：system_prompt 中约定文件规范（大纲放 outline.md、人物放 characters.md、章节放 chapters/xx.md），Agent 按约定自行创建。

## 十二、Embedding 模型切换：MiniLM → BGE

### 变更内容

将 `paraphrase-multilingual-MiniLM-L12-v2` 替换为 `BAAI/bge-small-zh-v1.5`。

- **维度不同**：MiniLM = 384 维，BGE-small-zh = **512 维**
- 但旧的 3 个 embedding 文件在阶段四会被整体删除，新 RAG tool（任务 2.3）是全新代码，直接用 512 维
- BGE 是中文专精模型，中文 MTEB 排名顶级，比多语言通用模型在中文场景表现更好

> ⚠️ **向量库不兼容**：如果项目中已有 ChromaDB 数据（384 维 collection），切换到 512 维后旧 collection **无法使用**，需要在数据迁移阶段重建所有 collection（见阶段四的"数据迁移"章节）。

### 需要修改的文件（3 处 MODEL_NAME）

| 文件 | 当前值 | 状态 |
|---|---|---|
| `backend/app/services/vector_store_service.py:34` | `MODEL_NAME = "paraphrase-multilingual-MiniLM-L12-v2"` | 删除（阶段四整个文件会被删） |
| `backend/app/services/chapter_vector_service.py:38` | `MODEL_NAME = "paraphrase-multilingual-MiniLM-L12-v2"` | 删除（阶段四整个文件会被删） |
