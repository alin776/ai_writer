# ContentOperator 迁移指南

## 迁移策略

采用 **渐进式迁移**，分三个阶段：

```
阶段1：新增    → 添加 operate_apply，不改现有代码
阶段2：共存    → 更新示例，推荐新工具，保留旧工具
阶段3：弃用    → 移除旧示例，标记 apply_chapter_edit 为内部使用
```

## 阶段1：新增（低风险）

### 1.1 新增文件

```bash
# 创建 operate_tools.py
touch backend/app/services/agent/tools/operate_tools.py
```

### 1.2 注册工具

```python

from .operate_tools import (

# 添加到 __all__
__all__ = [
    # ... 现有 ...
    "operate_apply",
    "operate_apply_tool",

```

### 1.3 添加到工具分类

```python
# backend/app/services/agent/core/tool_dispatcher.py

OPERATION_TOOLS = [
    "apply_chapter_edit",
    "operate_apply",        # 新增
    # ...
]
```

### 1.4 验证

```bash

# 验证工具可被调用

```

## 回滚方案

### 快速回滚

```python
# 如果 operate_apply 出现问题

# 1. 在 tool_dispatcher.py 中移除
OPERATION_TOOLS = [
    "apply_chapter_edit",
    # "operate_apply",  # 注释掉
    ...
]

# 2. 在 planning_examples.py 中切换回旧版本
PLANNING_EXAMPLES_VERSION = "v1"
```

### 完整回滚

```bash
# 恢复到改动前的版本
git checkout HEAD~1 -- backend/app/services/agent/tools/operate_tools.py
git checkout HEAD~1 -- backend/app/services/agent/prompts/planning_examples.py
```

## 迁移检查清单

### 阶段1 完成标准
```
□ operate_tools.py 文件创建完成
□ ContentOperator 类实现完成
□ operate_apply 工具可正常调用
□ 工具已添加到 OPERATION_TOOLS
□ 单元测试通过
```

### 阶段2 完成标准
```
□ 工具描述已更新
□ 新示例已添加
□ 旧示例仍保留（兼容）
□ 集成测试通过
□ 生产环境灰度验证通过
□ 无明显错误增加
```

### 阶段3 完成标准
```
□ 旧示例已移除
□ apply_chapter_edit 标记为内部使用
□ 文档已更新
□ 确认无外部直接调用 apply_chapter_edit
```

## 时间规划建议

| 阶段 | 预计耗时 | 风险等级 |
|------|---------|---------|
| 阶段1：新增 | 1-2天 | 低 |
| 阶段2：共存 | 1周 | 中 |
| 阶段3：弃用 | 视情况 | 需评估 |

**建议**：阶段2 至少运行1周，收集足够数据后再决定是否进入阶段3。
