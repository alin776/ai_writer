# Operate SubAgent 总体规划

## 背景

当前架构中，Planning-Executor 模式已经初步成型：
- **Planning**：决定任务流程
- **Explore SubAgent**：收集上下文（已实现，explore_tools.py）
- **Create 工具**：创作内容（smart_rewrite, smart_continue, smart_insert）
- **Operate 工具**：应用修改（多个分散工具）

**核心问题**：用户调用 AI Agent 的目的是**让 AI 生成内容**，所有需要 AI 的场景都是 `Create → Operate` 的流程。

**现有 Operate 工具（分散）**：
| 工具 | 功能 | 需要 AI 生成？ |
|------|------|---------------|
| apply_chapter_edit | 追加/替换/插入内容 | ✓ 需要 |
| update_chapter_title | 更新章节标题 | ✓ 需要（AI起标题） |
| create_chapter | 创建新章节 | ✓ 需要（AI写内容+起标题） |
| update_chapter_content | 整体替换内容 | ✗ 用户自己操作 |
| delete_chapter | 删除章节 | ✗ 用户自己操作 |

**问题**：
1. Planning 必须显式安排 `locate_content` 定位任务
2. 参数传递复杂（$ref 引用 paragraph_index, node_id）
3. 多个工具分散，Planning 需要记忆各工具用途
4. 容易出错，AI 规划不稳定

## 目标

将 Operate 升级为统一的 SubAgent，实现：
- **统一入口**：`operate_apply` 作为唯一入口，接收 Create 工具的输出
- **自动定位**：内部调用 locate_content（仅 replace/insert 需要）
- **意图路由**：根据 operation 自动选择底层工具
- **简化 Planning**：从3任务降为2任务

## 核心设计理念

**判断标准：是否需要 AI 生成内容？**
- 需要 → 走 operate_apply（Create → Operate）
- 不需要 → 用户自己在 UI 操作

| 场景 | 用户能自己做？ | 需要 AI？ | 走 operate_apply？ |
|------|---------------|----------|-------------------|
| 续写 | ✗ | ✓ | ✓ append |
| 改写部分 | ✗ | ✓ | ✓ replace |
| 插入 | ✗ | ✓ | ✓ insert |
| 重写整章 | ✗ | ✓ | ✓ content |
| 写新章节 | ✗ | ✓ | ✓ create |
| 改进标题 | ✗ | ✓ | ✓ title |
| 删除章节 | ✓ 点击删除 | ✗ | ✗ 用户自己操作 |
| 粘贴替换 | ✓ 复制粘贴 | ✗ | ✗ 用户自己操作 |

## 支持的操作类型

| operation | 说明 | 底层工具 | 需要定位 |
|-----------|------|----------|---------|
| append | 续写，追加到章节末尾 | apply_chapter_edit(append) | ✗ |
| replace | 改写，替换指定段落 | apply_chapter_edit(replace) | ✓ (原文匹配) |
| insert | 插入内容 | apply_chapter_edit(insert) | ✓ (语义定位) |
| content | 整体替换章节内容 | apply_chapter_edit(replace_all) | ✗ |
| create | 写新章节（标题+内容） | create_chapter | ✗ |
| title | 改进章节标题 | update_chapter_title | ✗ |

**说明**：所有修改内容的操作都通过 `apply_chapter_edit` 走 HITL 确认流程。

## 架构对比

### 改造前（分散工具 + 手动定位）
```
用户: "帮我续写第5章"
  ├─ Task 1: explore_content  → 收集上下文
  ├─ Task 2: smart_continue   → 创作内容
  └─ Task 3: apply_chapter_edit → 写入

用户: "帮我改写第3段"
  ├─ Task 1: locate_content   → 定位第3段 ⚠️ 必须手动安排
  ├─ Task 2: smart_rewrite    → 改写
  └─ Task 3: apply_chapter_edit → 写入 ⚠️ 复杂 $ref

用户: "帮我写第六章"
  ├─ Task 1: explore_content  → 收集上下文
  ├─ Task 2: smart_continue   → 创作内容
  └─ Task 3: create_chapter   → 新建章节 ⚠️ 还要起标题？
```

Planning 需要：
- 记忆多个不同工具的用法
- 判断何时需要 locate_content
- 生成复杂的 $ref 引用传递定位参数

### 改造后（统一入口 + 自动路由）
```
用户: "帮我续写第5章"
  ├─ Task 1: smart_continue   → 创作内容
  └─ Task 2: operate_apply(operation="append")
      └─ 内部: apply_chapter_edit(append)

用户: "帮我改写第3段"
  ├─ Task 1: smart_rewrite    → 改写
  └─ Task 2: operate_apply(operation="replace", original_text=原文)
      ├─ 内部: locate_content（自动定位）
      └─ 内部: apply_chapter_edit(replace)

用户: "帮我重写整个第五章"
  ├─ Task 1: smart_rewrite    → 重写整章内容
  └─ Task 2: operate_apply(operation="content", content=新内容)
      └─ 内部: apply_chapter_edit(replace_all) → HITL确认

用户: "帮我写第六章"
  ├─ Task 1: smart_continue   → 创作内容 + 生成标题
  └─ Task 2: operate_apply(operation="create", title=标题, content=内容)
      └─ 内部: create_chapter(title, content)

用户: "帮我想个更好的标题"
  ├─ Task 1: (AI生成新标题)
  └─ Task 2: operate_apply(operation="title", title=新标题)
      └─ 内部: update_chapter_title(title)
```

Planning 只需：
- 记忆 `operate_apply` 一个工具
- 传入 operation 和相关参数，SubAgent 自动处理

## 设计原则

1. **Create → Operate**：operate_apply 是 Create 工具输出的统一接收者
2. **自动定位**：replace/insert 自动调用 locate_content，无需 Planning 安排
3. **向后兼容**：保留所有现有底层工具，新增统一入口
4. **简单判断**：需要 AI 生成内容 → operate_apply，不需要 → 用户自己操作

## 预期收益

1. **Planning 简化**：工具数量从多个降为1个，任务数减少33%
2. **出错率降低**：消除手动定位参数传递
3. **代码内聚**：定位逻辑和路由逻辑封装在 SubAgent 内部
4. **易于理解**：一个简单判断标准（需要 AI 生成？）
5. **统一接口**：Create 工具的输出统一由 operate_apply 处理
