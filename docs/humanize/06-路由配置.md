# AI指纹消融 - 路由配置文档

## 文档说明
本文档说明如何将AI指纹消融功能集成到现有的侧边栏和路由体系，示例与当前`src/router/index.tsx`、`src/components/layout/Sidebar.tsx`的结构保持一致。

---

## 1) 修改侧边栏

**文件路径**: `src/components/layout/Sidebar.tsx`

1. 导入图标（位于现有图标列表中）。
2. 在`mainNavItems`（创作分组）中追加菜单项，保持与作品、知识库同级。

```typescript
import {
  BookOpen,
  Settings,
  Library,
  Wand2, // 新增：AI指纹消融
  // ... 其他图标
} from 'lucide-react';

const mainNavItems: NavItem[] = [
  { id: 'works', label: '作品管理', icon: BookOpen, path: '/works' },
  { id: 'knowledge', label: '知识库', icon: Library, path: '/knowledge' },
  { id: 'humanize', label: 'AI 指纹消融', icon: Wand2, path: '/humanize' },
];
```

> 说明：侧边栏已存在`serviceNavItems`、`adminNavItems`等分组，如需权限控制可在该项上设置`roles`（例如`roles: ['vip']`），并保持逻辑与现有实现一致。

---

## 2) 修改路由配置

**文件路径**: `src/router/index.tsx`

### 步骤1：添加懒加载

```typescript
const HumanizeView = React.lazy(() => import('../views/HumanizeView'));
```

将其放在其他懒加载视图旁边（如HomeView、WorksView）。

### 步骤2：在 AuthLayout 子路由中注册

当前项目使用`AuthLayout`作为父级，子路由通过`children`挂载；保持`SuspenseWrapper`一致，按需增加`ProtectedRoute`或`ErrorBoundary`。

```typescript
{
  element: <AuthLayout />,
  children: [
    // ...现有受保护路由
    {
      path: '/humanize',
      element: (
        <SuspenseWrapper>
          <HumanizeView />
        </SuspenseWrapper>
      ),
    },
  ],
}
```

> 如需额外权限校验，可改为`<ProtectedRoute><SuspenseWrapper>...`，并可在外层包裹`<ErrorBoundary>`保持与管理员路由的容错一致。

### 步骤3：Loading 组件

保持与现有`LoadingFallback`/`SuspenseWrapper`实现一致，无需额外修改。

---

## 3) 验证配置

- `npm run dev` 后访问 `/humanize`，确认加载正常。
- 侧边栏“创作”分组出现“AI 指纹消融”并能高亮。
- 刷新/深链到`/humanize`时布局、权限与其他受保护页面一致。

---

## 4) 可选：添加快捷入口

- **首页卡片**：在`HomeView`中新增链接卡片跳转`/humanize`。
- **编辑器按钮**：在`EditorView`工具栏添加跳转按钮（使用`useNavigate`）。

---

## 5) 路由权限与容错

- 角色控制：在侧边栏项上配置`roles`，并在`ProtectedRoute`或`AuthLayout`内复用现有权限逻辑。
- 错误边界：如希望与管理后台一致，可在`/humanize`元素外包裹`ErrorBoundary`以兜底渲染错误状态。

---

## 6) 环境变量与API前缀

- `VITE_API_BASE_URL`需与后端挂载前缀一致（例如`http://localhost:8000/api`或`http://localhost:8000/api/v1`）。
- HumanizeService 内使用的路径为`/humanize/*`；如果后端采用`/api/v1/humanize`，应在`VITE_API_BASE_URL`中带上`/api/v1`，避免二次拼接错误。
