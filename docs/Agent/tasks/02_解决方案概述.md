# ai_writer 记忆功能改进方案概述

## 目标

解决ai_writer项目中Agent的两个核心记忆问题：

### 🔴 问题1：Agent没有对话上下文（最严重）
每次对话只看到当前消息，看不到历史 → 导致Agent"失忆"

### 🟡 问题2：会话状态未持久化（次要）
服务重启后会话丢失（需要先解决问题1）

## 核心问题详解

### 问题1：对话历史加载缺失

**当前代码**（`langgraph_agent.py:1278`）：
```python
# ❌ 每次都只传入当前消息
initial_state = {
    "messages": [HumanMessage(content=message)],  # 只有1条！
}
```

**影响**：Agent每次对话都像"失忆"，看不到之前说了什么

### 问题2：使用MemorySaver

**当前代码**（`langgraph_agent.py:518`）：
```python
self.checkpointer = MemorySaver()  # 仅内存存储
```

**影响**：服务重启后会话丢失

## 改进方案步骤（按优先级）

### 🔴 第一阶段：修复对话历史加载（P0，必须）

**问题**：每次对话只传入当前消息，Agent看不到历史

**解决**：从Checkpointer加载历史messages，然后追加新消息

**修改位置**：`ai_writer/backend/app/services/agent/langgraph_agent.py:1278`

**核心代码**：
```python
# ✅ 修改后
saved_checkpoint = self.checkpointer.get(config)
if saved_checkpoint:
    messages = saved_checkpoint.channel_values.get("messages", [])
    messages.append(HumanMessage(content=message))  # 追加
else:
    messages = [HumanMessage(content=message)]

initial_state = {
    "messages": messages,  # ✅ 包含完整历史
    ...
}
```

**工作量**：2-3小时
**文档**：`07_修正_真正的上下文记忆问题.md`、`09_实施方案_ai_writer对话历史管理.md`

---

### 🟡 第二阶段：实现Redis Checkpointer（P1，推荐）

**问题**：MemorySaver不持久化，服务重启后会话丢失

**解决**：创建Redis Checkpointer替代MemorySaver

**文件位置**：`ai_writer/backend/app/services/agent/memory/redis_checkpointer.py`

**功能**：
- 实现LangGraph的BaseCheckpointer接口
- 使用Redis存储会话状态
- 支持TTL自动过期

**工作量**：3-4小时
**文档**：`03_实现LangGraph_Redis_Checkpointer.md`

---

### 🟢 第三阶段：添加记忆压缩（P2，可选）

**问题**：对话历史过长导致token溢出

**解决**：自动压缩旧消息为摘要

**功能**：
- 保留最近10条原文
- 旧消息压缩为摘要
- 使用LLM生成摘要

**工作量**：2小时
**文档**：`09_实施方案_ai_writer对话历史管理.md`（步骤3）

---

### 🟢 第四阶段：深度集成MemoryManager（P2，可选）

**任务**：集成现有的MemoryManager系统

**功能**：
- 自动保存对话历史到Redis
- 加载用户偏好和画像
- 记忆管理API

**工作量**：1天

## 技术实现细节

### Redis Checkpointer 数据结构

```python
# Redis Key 结构
checkpoint:{thread_id}:{checkpoint_id} -> JSON(AgentState)
checkpoint_list:{thread_id} -> List[checkpoint_id]

# 示例数据
{
    "messages": [...],
    "work_id": "uuid",
    "chapter_id": "uuid",
    "intent": "writing",
    "context": {...},
    "agent_steps": [...],
    "timestamp": "2025-11-04T14:00:00"
}
```

### 会话恢复流程

```python
# 1. 用户发起新请求，带上conversation_id
POST /agent/chat/stream
{
    "message": "继续写第三章",
    "conversation_id": "abc-123-def",
    "work_id": "work-456"
}

# 2. Agent从Redis加载上一次的状态
state = redis_checkpointer.get(thread_id="abc-123-def")

# 3. Agent基于历史状态继续执行
result = agent_graph.ainvoke(state, config={"thread_id": "abc-123-def"})

# 4. 执行完成后自动保存新状态到Redis
redis_checkpointer.put(thread_id="abc-123-def", state=new_state)
```

## 预期效果

### 改进前
- ❌ 服务重启后对话历史丢失
- ❌ 用户需要重复提供背景信息
- ❌ Agent无法记住之前的上下文

### 改进后
- ✅ 会话状态持久化到Redis
- ✅ 跨会话恢复对话历史
- ✅ 服务重启不影响用户体验
- ✅ Agent能够记住完整的上下文

## 风险评估

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| Redis故障导致状态丢失 | 高 | 低 | 实现降级机制，回退到MemorySaver |
| 大量会话导致Redis内存不足 | 中 | 中 | 实现TTL过期机制，定期清理 |
| 状态序列化性能问题 | 低 | 低 | 优化序列化方式，使用msgpack |
| 与现有代码冲突 | 中 | 低 | 充分测试，保持向后兼容 |
