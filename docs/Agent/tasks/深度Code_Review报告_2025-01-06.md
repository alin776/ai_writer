### 3. 消息累积问题分析 ✅

**深度分析**:

通过手动trace和测试验证，确认：
- ❌ **不存在**消息重复累积bug
- ✅ 原始逻辑是正确的
- ✅ operator.add机制正常工作

**测试证据**:
```
场景：简单工具调用
初始: [HumanMessage]
返回: [AIMessage(decision), ToolMessage(result), AIMessage(response)]
最终: [HumanMessage, AIMessage(decision), ToolMessage(result), AIMessage(response)]
消息总数: 4 ✅
```

**结论**:
Token数波动的真正原因是：
1. 消息历史随对话轮次自然增长
2. 不同工具返回的结果长度差异大
3. 原有清理策略不够激进

---

### 4. 智能消息清理策略 ✅

**位置**: `langgraph_agent.py:1448-1494`

**原策略问题**:
- 阈值太高（>10条才清理）
- 保留太多（保留8条）
- 简单粗暴（不区分消息类型）

**新策略特性**:

1. **更早触发**: 8条即触发（降低20%）
2. **智能分类**:
   - SystemMessage: 保留全部
   - HumanMessage: 保留最近1条
   - AIMessage + ToolMessage: 保留最近2对交互

3. **压缩效果**:
   ```
   10条 -> 6条 (压缩率40%)
   15条 -> 6条 (压缩率60%)
   20条 -> 6条 (压缩率70%)
   ```

4. **保持顺序**: 按原始顺序重组消息

**优势**:
- ✅ 大幅降低Token使用
- ✅ 保留关键上下文
- �� 动态调整压缩率
