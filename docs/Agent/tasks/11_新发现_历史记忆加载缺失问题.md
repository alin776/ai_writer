# 新发现：Agent 历史记忆加载缺失问题

## 📅 发现时间：2025-11-04

## 🚨 问题描述

虽然我们已经修复了 operator.add 消息重复问题，但发现了一个**更严重的问题**：

**Agent 无法记住之前的对话内容！**

### 测试证据

```
[第2轮] 用户: 我们刚才聊了什么?
[第2轮] 响应: 你好！我没有保留之前的对话记录，每一次交流都是全新的开始。
```

**矛盾现象**：
- ✅ 消息数量正确（2→4→6）- operator.add 工作正常
- ❌ AI 响应显示没有记忆 - 历史加载失败

---

## 🔍 根本原因

### 问题代码（langgraph_agent.py:1327）

```python
async def chat(
    self,
    message: str,
    conversation_id: Optional[str] = None,
    ...
):
    # ❌ 问题：只传入当前消息，没有加载历史
    initial_state = {
        "messages": [HumanMessage(content=message)],  # 只有1条！
        "work_id": work_id,
        "chapter_id": chapter_id,
        ...
    }

    config = {"configurable": {"thread_id": conversation_id or "default"}}

    # LangGraph 会从 checkpoint 加载历史，但 initial_state 会覆盖！
    result = await self.graph.ainvoke(initial_state, config)
```

### 为什么消息数量是对的？

因为 **operator.add 会追加**：

1. 第1轮：initial_state = [msg1] → checkpoint保存 [msg1, ai1]
2. 第2轮：initial_state = [msg2] → operator.add 追加 → [msg1, ai1, msg2, ai2]

所以消息数量对了，但 **LLM 只看到 [msg2]**，没看到完整历史！

---

## ✅ 正确的实现方式

### 方案1：从 Checkpoint 加载历史（推荐）

```python
async def chat(
    self,
    message: str,
    conversation_id: Optional[str] = None,
    ...
):
    config = {"configurable": {"thread_id": conversation_id or "default"}}

    # ✅ 从 checkpoint 加载历史
    try:
        saved_state = self.checkpointer.get(config)
        if saved_state:
            # 加载历史消息
            messages = saved_state.channel_values.get("messages", [])
            messages.append(HumanMessage(content=message))  # 追加新消息
        else:
            # 新对话
            messages = [HumanMessage(content=message)]
    except:
        # 降级处理
        messages = [HumanMessage(content=message)]

    initial_state = {
        "messages": messages,  # ✅ 包含完整历史
        "work_id": work_id,
        "chapter_id": chapter_id,
        ...
    }

    result = await self.graph.ainvoke(initial_state, config)
```
