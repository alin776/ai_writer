## 🏗️ 当前架构

### 核心架构改进

```
新架构流程：
API请求
  ↓
TraceMiddleware（分布式追踪）
  ↓
MonitoringMiddleware（API监控）
  ↓
Agent._handle_*()（节点处理）
  ↓
Action.prepare()（准备参数，返回system_prompt）
  ↓
_handle_agent_with_tools()（统一LLM调用）
  ↓
ChatOpenAI（带MonitoringCallbackHandler）
  ↓
监控指标记录 ✅
```

### 关键改进点

1. **Action层职责清晰化**
   - ❌ 旧架构：Action直接调用LLM（绕过监控）
   - ✅ 新架构：Action只准备参数，Agent统一调用LLM

2. **100%监控覆盖**
   - ✅ API层：TraceMiddleware + MonitoringMiddleware
   - ✅ Agent层：关键节点监控
   - ✅ LLM层：MonitoringCallbackHandler

3. **框架利用率提升**
   - ❌ 旧架构：约30%框架利用率
   - ✅ 新架构：90%+框架利用率

## 💡 关键技术决策

### 决策1：保留Action层

**理由**：
- Action层封装重要的业务逻辑（小说阶段判断等）
- Planning模式需要自定义执行流程
- Prompt工程需要集中管理

**方案**：轻量化Action职责，只负责参数准备

### 决策2：统一使用ChatOpenAI

**理由**：
- 完全拥抱LangChain/LangGraph框架
- 100%监控覆盖
- 便于维护和扩展

**方案**：所有LLM调用走ChatOpenAI，保留HTTPAIService作为降级方案

### 决策3：分阶段实施

**理由**：
- 降低风险
- 快速验证
- 逐步迁移

**方案**：P0验证可行性 → P1全面迁移 → P2监控完善

## 🔧 开发指南

### 如何添加新的Action

1. **继承BaseAction**并实现prepare()方法：
```python
class MyAction(BaseAction):
    def __init__(self):
        super().__init__("my_action", "描述")

    async def prepare(self, state: Dict) -> ActionResult:
        # 1. 提取参数
        # 2. 构建system_prompt
        # 3. 返回ActionResult
        return ActionResult(
            status=ActionStatus.COMPLETED,
            system_prompt=prompt,
            metadata={"key": "value"}
        )
```

2. **在Agent中添加节点**：
```python
async def _handle_my_action(self, state: AgentState) -> AgentState:
    action = MyAction()
    prep_result = await action.prepare(state)

    if not prep_result.success:
        return self._create_error_state(state, prep_result.error)

    return await self._handle_agent_with_tools(
        state,
        prep_result.system_prompt,
        prep_result.metadata
    )
```
