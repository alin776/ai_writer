## 1. Memory相关表

### 1.1 memory_snapshots (记忆快照表)

存储Memory系统的快照,用于恢复历史状态。

```sql
CREATE TABLE memory_snapshots (
    id BIGSERIAL PRIMARY KEY,
    snapshot_id VARCHAR(50) UNIQUE NOT NULL,
    user_id VARCHAR(50) NOT NULL,
    conversation_id VARCHAR(50) NOT NULL,
    snapshot_data JSONB NOT NULL,  -- 快照内容
    description TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    INDEX idx_user_conversation (user_id, conversation_id),
    INDEX idx_created_at (created_at)
);
```

## 2. 版本控制相关表

### 2.1 versioned_contents (版本化内容表)

```sql
CREATE TABLE versioned_contents (
    id BIGSERIAL PRIMARY KEY,
    content_id VARCHAR(50) UNIQUE NOT NULL,
    user_id VARCHAR(50) NOT NULL,
    base_content TEXT NOT NULL,
    current_version_id VARCHAR(50),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    INDEX idx_user_id (user_id),
    INDEX idx_content_id (content_id)
);
```

### 2.2 content_versions (内容版本表)

```sql
CREATE TABLE content_versions (
    id BIGSERIAL PRIMARY KEY,
    version_id VARCHAR(50) UNIQUE NOT NULL,
    content_id VARCHAR(50) NOT NULL,
    parent_version_id VARCHAR(50),
    patches JSONB NOT NULL,  -- 补丁列表
    description TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (content_id) REFERENCES versioned_contents(content_id),
    INDEX idx_content_id (content_id),
    INDEX idx_parent_version (parent_version_id)
);
```

### 2.3 version_branches (版本分支表)

```sql
CREATE TABLE version_branches (
    id BIGSERIAL PRIMARY KEY,
    branch_id VARCHAR(50) UNIQUE NOT NULL,
    content_id VARCHAR(50) NOT NULL,
    branch_name VARCHAR(100) NOT NULL,
    base_version_id VARCHAR(50) NOT NULL,
    head_version_id VARCHAR(50) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (content_id) REFERENCES versioned_contents(content_id),
    INDEX idx_content_id (content_id)
);
```

## 3. 成本追踪相关表

### 3.1 api_call_logs (API调用日志表)

```sql
CREATE TABLE api_call_logs (
    id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(50) NOT NULL,
    conversation_id VARCHAR(50),
    model_name VARCHAR(50) NOT NULL,
    provider VARCHAR(20) NOT NULL,  -- openai, deepseek, anthropic
    input_tokens INTEGER NOT NULL,
    output_tokens INTEGER NOT NULL,
    total_tokens INTEGER NOT NULL,
    cost DECIMAL(10, 6) NOT NULL,
    duration_ms INTEGER,
    success BOOLEAN DEFAULT true,
    error_message TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    INDEX idx_user_id (user_id),
    INDEX idx_created_at (created_at),
    INDEX idx_model_name (model_name)
);
```

### 3.2 user_cost_stats (用户成本统计表)

```sql
CREATE TABLE user_cost_stats (
    id BIGSERIAL PRIMARY KEY,
    user_id VARCHAR(50) NOT NULL,
    date DATE NOT NULL,
    total_cost DECIMAL(10, 2) NOT NULL,
    total_tokens INTEGER NOT NULL,
    api_calls INTEGER NOT NULL,
    model_breakdown JSONB,  -- 各模型成本明细
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    UNIQUE (user_id, date),
    INDEX idx_user_date (user_id, date)
);
```

## 4. 质量评估相关表

### 4.1 quality_evaluations (质量评估记录表)

```sql
CREATE TABLE quality_evaluations (
    id BIGSERIAL PRIMARY KEY,
    evaluation_id VARCHAR(50) UNIQUE NOT NULL,
    content_id VARCHAR(50),
    user_id VARCHAR(50) NOT NULL,
    overall_score DECIMAL(3, 1) NOT NULL,  -- 0.0-10.0
    dimension_scores JSONB NOT NULL,
    passes BOOLEAN NOT NULL,
    feedback TEXT,
    suggestions JSONB,
    context TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    INDEX idx_user_id (user_id),
    INDEX idx_content_id (content_id),
    INDEX idx_overall_score (overall_score),
    INDEX idx_created_at (created_at)
);
```

### 4.2 quality_loop_history (质量循环历史表)

```sql
CREATE TABLE quality_loop_history (
    id BIGSERIAL PRIMARY KEY,
    loop_id VARCHAR(50) UNIQUE NOT NULL,
    content_id VARCHAR(50),
    user_id VARCHAR(50) NOT NULL,
    iterations INTEGER NOT NULL,
    final_score DECIMAL(3, 1) NOT NULL,
    initial_score DECIMAL(3, 1),
    improvement DECIMAL(3, 1),
    iteration_details JSONB,  -- 每次迭代的详情
    total_duration_ms INTEGER,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    INDEX idx_user_id (user_id),
    INDEX idx_final_score (final_score)
);
```

## 5. 索引设计

### 5.1 推荐的索引

```sql
-- Memory快照查询优化
CREATE INDEX idx_memory_snapshots_user_conv
ON memory_snapshots(user_id, conversation_id, created_at DESC);

-- 版本历史查询优化
CREATE INDEX idx_content_versions_content_created
ON content_versions(content_id, created_at DESC);

-- 成本统计查询优化
CREATE INDEX idx_api_call_logs_user_date
ON api_call_logs(user_id, created_at DESC);

-- 质量评估查询优化
CREATE INDEX idx_quality_evaluations_user_score
ON quality_evaluations(user_id, overall_score DESC, created_at DESC);
```

### 5.2 分区表 (可选,高并发场景)

对于高并发场景,可以对日志表进行分区:

```sql
-- API调用日志按月分区
CREATE TABLE api_call_logs (
    id BIGSERIAL,
    user_id VARCHAR(50) NOT NULL,
    -- ... 其他字段
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) PARTITION BY RANGE (created_at);

CREATE TABLE api_call_logs_2025_10 PARTITION OF api_call_logs
FOR VALUES FROM ('2025-10-01') TO ('2025-11-01');

CREATE TABLE api_call_logs_2025_11 PARTITION OF api_call_logs
FOR VALUES FROM ('2025-11-01') TO ('2025-12-01');
```

## 🔧 Redis数据结构

### Memory分层存储

```
# 短期记忆 (List)
user:{user_id}:memory:short => [mem1, mem2, mem3, ...]

# 中期记忆 (Sorted Set, 按重要度排序)
user:{user_id}:memory:medium => {mem_id: importance_score}

# 长期记忆 (String, 压缩摘要)
user:{user_id}:memory:long => "compressed summary..."
```

### 会话状态

```
# 会话状态 (Hash)
conversation:{conv_id}:state => {
    "current_node": "writing",
    "messages": [...],
    "context": {...}
}
```

### 成本缓存

```
# 用户今日成本 (String)
user:{user_id}:cost:today => "12.50"

# 成本限额检查 (String, TTL=1天)
user:{user_id}:cost:limit => "100.00"
```
