## 1. 项目背景

### 1.1 当前状态

AI Writer 项目已实现基于 LangGraph 的 Agent 系统，提供了基础的智能写作助手功能：

**✅ 已有优势**:
- LangGraph 框架（灵活的图编排）
- 流式响应（SSE）
- 记忆系统（Redis）
- HITL 人机协同
- 工具注册系统
- RAG 知识检索
- 4个Agent角色（Planning/Writing/Reflection/Parallel）

**❌ 待改进点**:
- Memory系统较简单（FIFO策略）
- 工具调用不够标准化
- 缺乏版本管理
- 缺乏质量循环机制
- 缺乏内容优化Prompt
- 缺乏模型分级策略

### 1.2 改造动机

通过研究 5 个优秀的开源项目：
- novel-multi-agents
- pulpgen
- novel-agent
- MetaGPT_novels
- novel-ai-agent-Chinese

我们提取了多个高度可移植（100%）的设计模式，计划对现有 Agent 系统进行增强改造，打造业界领先的 AI 写作 Agent 系统。

## 2. 核心原则

### 2.1 零破坏原则 ⭐⭐⭐⭐⭐

**承诺：绝对不影响现有功能**

#### 2.1.1 路由隔离

```
✅ 普通AI模式: /api/v1/ai/*
   ├─ /ai/complete   (续写)
   ├─ /ai/polish     (润色)
   ├─ /ai/translate  (翻译)
   ├─ /ai/expand     (扩写)
   └─ /ai/summarize  (总结)

   → 使用服务: OpenAIService / HTTPAIService
   → 位置: app/services/ai/
   → 状态: 完全不动！

✅ Agent模式: /api/v1/agent/*
   ├─ /agent/chat    (对话)
   ├─ /agent/plan    (规划)
   └─ /agent/hitl    (人机协同)

   → 使用服务: WritingAgentGraph (LangGraph)
   → 位置: app/services/agent/
   → 状态: 渐进式增强
```

#### 2.1.2 服务隔离

```
app/services/
├─ ai/              ← 完全不动
│  ├─ openai_service.py
│  ├─ http_ai_service.py
│  ├─ prompts.py
│  └─ ...
│
└─ agent/           ← 所有改造都在这里
   ├─ langgraph_agent.py
   ├─ agents/
   ├─ memory/
   └─ tools/
```

#### 2.1.3 配置开关控制

所有新功能都支持配置开关，随时可以关闭：

```python

    ENABLE_MODEL_SELECTION: bool = True      # 智能模型选择
    ENABLE_SMART_PROMPTS: bool = True        # 优化的Prompt库
```

### 3.2 核心设计模式

#### 3.2.1 工具驱动通信模式（novel-multi-agents）

**精华**：Agent 通过工具（Tool）进行数据共享，LLM 完全可见工具调用过程。

```python
# 工具定义
@function_tool
def store_novel_outline(outline: NovelOutline) -> str:
    """存储小说大纲"""
    novel_storage.outline = outline
    return f"保存了小说大纲: {outline.title}"

# Agent 定义
outline_agent = Agent(
    name="outline_agent",
    output_type=NovelOutline,  # 强类型输出
    tools=[store_novel_outline],
)
```

**价值**：
- ✅ Agent 间数据共享透明
- ✅ 类型安全
- ✅ 易于调试和监控

#### 3.2.2 补丁式版本管理（pulpgen）

**精华**：基础版本 + 增量补丁 = 当前版本

```
基础版本: "第一章内容..."
补丁1: INSERT 位置100 "新增的情节"
补丁2: REPLACE 位置200-250 "修改后的对话"
补丁3: DELETE 位置300-320

当前版本 = 应用所有补丁后的结果
```

**价值**：
- ✅ 完整版本历史
- ✅ 支持回滚
- ✅ 支持分支和合并
- ✅ 精确的变更追踪

#### 3.2.3 智能记忆系统（novel-agent）

**精华**：分层记忆 + 智能遗忘

```
短期记忆 (最近10条) → 完整保留
中期记忆 (最近100条) → 按重要度保留
长期记忆 (历史所有) → 压缩为摘要
```

**价值**：
- ✅ 高效的记忆管理
- ✅ 平衡性能和质量
- ✅ 支持大规模对话

#### 3.2.4 质量循环机制（novel-multi-agents）

**精华**：生成 → 评估 → 改进 → 重试（最多3次）

```
迭代1: 生成内容 → 评分7.0 → 未通过
迭代2: 改进生成 → 评分7.8 → 未通过
迭代3: 再次改进 → 评分8.5 → 通过！
```

**价值**：
- ✅ 自动提升内容质量
- ✅ 减少人工干预
- ✅ 可配置的质量标准

#### 3.2.5 四维度爽感优化（novel-ai-agent-Chinese）

**精华**：网文爽感公式

```
爽感 = 反转震撼(35%) + 期待升级(35%) + 场景描写(20%) + 对话设计(10%)
```

**价值**：
- ✅ 经过实战验证的Prompt
- ✅ 直接可用的创作技巧
- ✅ 显著提升内容吸引力

#### 3.2.6 模型分级策略（novel-ai-agent-Chinese）

**精华**：任务复杂度 → 模型选择

```
简单任务 (评估、分类) → 快速模型 (DeepSeek)
中等任务 (润色、扩写) → 均衡模型 (GPT-3.5)
复杂任务 (创作、规划) → 强力模型 (GPT-4)
```

**价值**：
- ✅ 成本优化 40-50%
- ✅ 自动化选择
- ✅ 性能和成本平衡

## 4. 改造目标

### 4.1 总体目标

**打造业界领先的 AI 写作 Agent 系统**

融合 5 个参考项目的精华，在现有 LangGraph 框架基础上，构建功能完善、性能优越、成本可控的智能写作助手。

### 4.2 阶段目标

#### 4.2.1 阶段一：核心基础设施改造（2-3周）

**目标**：打牢基础，提升系统可靠性

**具体目标**：

1. **增强 Memory 系统**
   - ✅ 实现分层记忆（短期/中期/长期）
   - ✅ 实现智能遗忘策略（非简单FIFO）
   - ✅ 实现状态快照与恢复
   - ✅ 支持版本历史追踪
   - 📊 **指标**：Memory检索速度 < 100ms

2. **标准化工具系统**
   - ✅ 实现工具驱动通信模式
   - ✅ 实现强类型输入输出
   - ✅ 添加工具调用日志和监控
   - ✅ 支持工具版本管理
   - 📊 **指标**：工具调用成功率 > 99%

3. **实现版本管理**
   - ✅ 实现补丁式版本控制（JSON格式）
   - ✅ 支持版本回滚
   - ✅ 支持版本分支和合并
   - ✅ 记录完整变更历史
   - 📊 **指标**：版本回滚速度 < 200ms

#### 4.2.2 阶段二：高价值功能集成（3-4周）

**目标**：快速提升内容质量和用户体验

**具体目标**：

1. **质量循环机制**
   - ✅ 实现生成 → 评估 → 改进 → 重试流程
   - ✅ 支持多维度评估（质量 + 字数 + 连贯性）
   - ✅ 生成智能反馈和改进建议
   - ✅ 自动优化Prompt
   - 📊 **指标**：质量评估准确率 > 80%，内容质量提升 +15%

2. **Prompt 库优化**
   - ✅ 集成 novel-ai-agent-Chinese 的 Prompt
   - ✅ 实现四维度爽感优化
   - ✅ 实现分阶段生成策略（起承转合终）
   - ✅ 支持用户偏好自定义
   - 📊 **指标**：用户满意度 > 4.5/5

3. **模型分级策略**
   - ✅ 实现任务复杂度自动判断
   - ✅ 实现模型智能选择
   - ✅ 实现成本追踪和估算
   - ✅ 支持多种LLM提供商
   - 📊 **指标**：API成本降低 40-50%

#### 4.2.3 阶段三：架构优化与完善（2-3周）

**目标**：长期可维护性和可扩展性

**具体目标**：

1. **引入 ARE 设计理念**
   - ✅ 标准化 Action 层（节点函数）
   - ✅ 增强 Role 层（Agent职责定义）
   - ✅ 实现 Environment 层（消息总线和状态管理中枢）
   - 📊 **指标**：代码可维护性评分 > 8/10

2. **批量生成优化**
   - ✅ 实现分散-填充算法
   - ✅ 优化全局上下文管理
   - ✅ 提升长篇小说生成质量
   - 📊 **指标**：长篇生成质量分数 +20%

3. **监控和可观测性**
   - ✅ 实现性能监控
   - ✅ 实现成本追踪
   - ✅ 实现质量分析和报表
   - ✅ 添加错误追踪和告警
   - 📊 **指标**：问题发现时间 < 5分钟
