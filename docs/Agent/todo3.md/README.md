# 上下文压缩方案研究

## 📚 文档说明

本目录包含了两种主流的AI上下文压缩方案的详细研究，基于对 **AI_Gen_Novel** 和 **MetaGPT_novels** 两个开源项目的深入分析。

## 🎯 什么是上下文压缩？

在长篇小说创作或复杂任务处理中，AI每次生成内容时需要大量的历史上下文信息。如果不经压缩直接发送所有内容，会导致：

- 💰 **Token消耗巨大**（按Token收费，成本很高）
- ⏱️ **响应速度慢**（处理大量文本需要时间）
- 🔄 **信息冗余**（很多历史信息可能用不上）

上下文压缩的核心目标：**在保持内容质量的前提下，大幅降低Token消耗和提升响应速度**。

## 📊 两种压缩方案概览

### 方案一：AI_Gen_Novel - 滚动记忆压缩

**核心思想：** 增量压缩，累积一定量新内容后才触发压缩

**特点：**
- ✅ 实现简单，易于理解
- ✅ Token节省率高达 **97%**
- ✅ 适合线性创作场景（如小说写作）
- ⚠️ 只维护单一压缩记忆

**详细说明：** [01-AI_Gen_Novel压缩方案.md](./01-AI_Gen_Novel压缩方案.md)

---

### 方案二：MetaGPT - 分层记忆系统

**核心思想：** 短期+长期双层记忆 + 向量检索去重

**特点：**
- ✅ 功能强大，支持复杂场景
- ✅ 智能去重机制
- ✅ Token节省率约 **60-80%**
- ⚠️ 实现较复杂，需要向量数据库支持

**详细说明：** [02-MetaGPT压缩方案.md](./02-MetaGPT压缩方案.md)

---

## 📈 效果对比

| 指标 | AI_Gen_Novel | MetaGPT |
|------|-------------|---------|
| **Token节省率** | ~97% | ~60-80% |
| **实现复杂度** | ⭐⭐ 简单 | ⭐⭐⭐⭐ 复杂 |
| **适用场景** | 长篇小说连续创作 | 多轮对话、代码项目 |
| **记忆类型** | 单一压缩记忆 | 短期+长期双层 |
| **检索方式** | 直接使用 | 关键词+向量搜索 |
| **持久化** | 文件保存 | 向量数据库 |
| **去重能力** | ❌ 无 | ✅ 智能去重 |

**详细对比：** [03-方案对比分析.md](./03-方案对比分析.md)
