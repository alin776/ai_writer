## 一、接口对接问题

### 1.1 缺失的 API 方法实现

前端文档 4.3 节只实现了 `createSession()`，但前端需要调用的接口还有：

| 后端接口 | 前端 agentApi 是否实现 | 问题 |
|---------|----------------------|------|
| `POST /sessions` | ✅ 已实现 | - |
| `POST /sessions/{id}/archive` | ❌ 未实现 | 关闭标签页时需要调用 |
| `GET /sessions/history` | ❌ 未实现 | 历史面板需要获取列表 |
| `POST /sessions/{id}/restore` | ❌ 未实现 | 恢复历史会话需要调用 |

**状态**: ✅ 已在前端文档 4.3 节补充完整实现

---

### 1.2 字段命名风格不一致

**后端响应（下划线命名）**：
```json
{ "work_id": "xxx", "chapter_id": "xxx", "created_at": "..." }
```

**前端类型（驼峰命名）**：
```typescript
interface ConversationSession {
  workId?: string;
  chapterId?: string;
  createdAt: string;
}
```

前端文档 3.3 节有映射说明，但 **实际代码中没有转换逻辑**。

**状态**: ✅ 已在前端文档 4.3 节添加字段转换函数 `transformSessionResponse()`

---

## 二、业务流程不完整

### 2.1 关闭会话 vs 归档会话 混淆

前端文档功能描述：
> "关闭会话时自动归档到历史记录"

但实际代码（4.6节）：
```typescript
const handleCloseSession = (targetSessionId: string) => {
  deleteSession(targetSessionId);  // ❌ 是删除，不是归档！
};
```

**问题**：`deleteSession` 直接删除本地数据，没有调用后端的 `POST /sessions/{id}/archive`。

**状态**: ✅ 已在前端文档 4.6 节修复，改为先调用归档 API 再删除本地数据

---

### 2.2 历史面板数据来源矛盾

前端文档说：
> "复用 ConversationHistory 作为历史面板"

但存在问题：
- 现有 `ConversationHistory` 从 **localStorage** 获取所有会话
- 历史面板应该调用 `GET /sessions/history` 获取 **已归档** 的会话
- 两者数据来源完全不同

**状态**: ✅ 已在前端文档中新增 4.7 节 HistoryPanel 组件实现

---

### 2.3 恢复历史会话逻辑缺失

后端提供了 `POST /sessions/{id}/restore` 返回完整会话数据（包含 messages），但前端：

1. 没有实现 `restoreSession` API 方法
2. 历史面板点击项后的处理逻辑没有写出来
3. 后端返回的 messages 如何与 localStorage 同步？

**状态**: ✅ 已在前端文档 4.3、4.7 节补充完整实现

---

## 三、数据存储一致性问题

### 3.1 消息存储位置矛盾

| 层级 | 后端说明 | 前端说明 |
|------|---------|---------|
| 消息完整内容 | LangGraph Checkpoint (TTL 7天) | localStorage |
| 恢复会话时 | 后端 restore 接口返回 messages | 从 localStorage 读取 |

**潜在问题**：
- 如果 localStorage 被清理，但后端 Checkpoint 还在，从哪恢复？
- 如果 Checkpoint 过期（7天），但 localStorage 还有，数据以谁为准？

**状态**: ✅ 已在后端文档 3.1 节和前端文档 4.8 节明确数据源优先级策略

---

### 3.2 消息角色名称不一致

**后端 restore 响应**：
```json
{ "role": "agent", "content": "..." }
```

**前端 Message 类型通常是**：
```typescript
{ role: "assistant", content: "..." }  // OpenAI 风格
```

**状态**: ✅ 已在后端文档 2.5 节和前端文档 4.3 节统一说明，后端使用 `assistant`

---

## 四、边界情况处理不足

### 4.1 会话数量限制

后端文档：
> `MAX_SESSIONS_PER_USER = 50`，超限返回 400 错误

前端文档：
> "支持无限标签（横向滚动）"

**矛盾**：前端没有对 50 会话限制做相应提示和处理。

**状态**: ✅ 已在前端文档 4.6 节添加会话数量限制的错误处理

---

### 4.2 降级策略不完整

前端文档 4.4 节的降级逻辑：
```typescript
} catch (error) {
  // 降级：使用前端生成的 ID
  persistence.createNewSession();  // ❌ 没有 conversationId
}
```

**问题**：降级创建的会话没有后端生成的 `conversationId`，后续调用 `/chat/stream` 时可能出问题。

**状态**: ✅ 已在前端文档 4.4 节完善降级策略，生成本地 UUID 并标记

---

### 4.3 `expires_at` 未处理

后端返回会话过期时间 `expires_at`（30天后），但前端：
- `ConversationSession` 类型中没有 `expiresAt` 字段
- 没有过期预警或自动清理逻辑

**状态**: ✅ 已在前端文档 3.1 节添加 `expiresAt` 字段说明
