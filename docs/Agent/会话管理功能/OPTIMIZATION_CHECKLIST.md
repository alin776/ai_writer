# 会话管理功能 - 优化检查清单

**创建时间**: 2025-11-08
**当前状态**: Sprint 1 完成，测试通过率 80%
**下一步**: 根据优先级逐步优化

---

## P0 - 紧急优化（影响功能稳定性）

### 1. 测试覆盖率提升
**当前问题**: 只有集成测试，缺少单元测试
**影响**: 代码重构时风险高，难以定位问题
**优化方案**:
- [ ] 添加 pytest 单元测试（每个API独立测试）
- [ ] 添加边界情况测试（空会话、无效ID、超大分支等）
- [ ] 添加并发测试（同时创建多个分支）
- [ ] 测试覆盖率目标：80%以上
**预计耗时**: 3-4小时

### 2. 错误处理增强
**当前问题**: 部分异常处理不够细致
**影响**: 用户可能看到不友好的错误信息
**优化方案**:
- [ ] 创建分支时，如果checkpoint为空，返回明确错误
- [ ] 切换分支时，如果分支不存在，返回404而非500
- [ ] 所有API添加统一的错误响应格式
- [ ] 添加错误码枚举（如：BRANCH_NOT_FOUND = 40401）
**预计耗时**: 2小时

### 3. Redis连接池配置外部化
**当前问题**: Redis配置硬编码在 agent.py 中
**影响**: 难以在不同环境切换配置
**代码位置**: `backend/app/api/v1/agent.py:39-56`
**优化方案**:
```python
# 移动到 backend/app/core/config.py
class Settings(BaseSettings):
    REDIS_HOST: str = "localhost"
    REDIS_PORT: int = 6379
    REDIS_DB: int = 1
    REDIS_MAX_CONNECTIONS: int = 10
    REDIS_TIMEOUT: int = 5
```
**预计耗时**: 1小时

## P1 - 重要优化（影响用户体验）

### 4. 分叉点语义优化
**当前问题**: 按checkpoint数量分叉，不是真实消息数
**影响**: 用户可能困惑（看到5条消息，但只有3个checkpoint）
**优化方案**:
- [ ] 解析checkpoint中的实际消息数量
- [ ] fork_point_message_index 改为基于真实消息索引
- [ ] 添加消息预览功能（显示分叉点的实际消息内容）
**技术难点**: 需要遍历checkpoint提取所有消息
**预计耗时**: 4-5小时

### 5. 性能优化
**当前问题**: 创建分支时逐个复制checkpoint（~500ms）
**影响**: 大量消息时创建分支慢
**优化方案**:
- [ ] 使用 Redis Pipeline 批量保存checkpoint
- [ ] 添加缓存层（Redis缓存分支元数据）
- [ ] 异步复制checkpoint（返回分支ID，后台复制）
- [ ] 添加性能监控日志
**目标**: 创建分支响应时间 < 200ms
**预计耗时**: 3-4小时

### 6. 分支命名优化
**当前问题**: 默认名称"分支-MMDD-HHMM"不够友好
**影响**: 用户难以区分多个分支
**优化方案**:
- [ ] 自动生成语义化名称（如"从'你好'分叉"）
- [ ] 支持自定义emoji前缀（📁、🌿、🔀）
- [ ] 添加分支描述字段
**预计耗时**: 2小时

### 7. 分支预览功能
**当前问题**: 切换分支前无法预览内容
**影响**: 用户需要切换后才知道分支内容
**优化方案**:
- [ ] 添加 `GET /branches/{id}/preview` 接口
- [ ] 返回分支前3条消息的摘要
- [ ] 显示分支创建时间和分叉点信息
**预计耗时**: 2-3小时

## P2 - 可选优化（锦上添花）

### 8. 分支管理增强
**当前问题**: 缺少分支重命名、删除功能
**影响**: 用户无法管理历史分支
**优化方案**:
- [ ] 添加 `PATCH /branches/{id}` - 重命名分支
- [ ] 添加 `DELETE /branches/{id}` - 删除分支（级联删除checkpoint）
- [ ] 添加分支归档功能（隐藏但不删除）
- [ ] 添加分支搜索功能（按名称、日期）
**预计耗时**: 4-5小时

### 9. 分支合并功能
**当前问题**: 无法合并两个分支
**影响**: 用户可能需要手动复制消息
**优化方案**:
- [ ] 设计分支合并算法
- [ ] 检测冲突（同一位置有不同消息）
- [ ] 添加 `POST /branches/{id}/merge` 接口
- [ ] 提供合并预览和确认机制
**技术难点**: 合并冲突解决策略
**预计耗时**: 8-10小时

### 10. 分支可视化优化
**当前问题**: 返回扁平列表，前端需自己构建树
**影响**: 前端逻辑复杂
**优化方案**:
- [ ] 后端构建完整的树形结构
- [ ] 支持查询参数 `?format=tree` 或 `?format=flat`
- [ ] 添加分支深度限制（防止无限递归）
**预计耗时**: 2-3小时

### 11. 监控和告警
**当前问题**: 无监控，生产问题难以发现
**影响**: 无法及时发现性能问题
**优化方案**:
- [ ] 添加 Prometheus 监控指标
- [ ] 监控分支创建成功率
- [ ] 监控API响应时间（P50/P95/P99）
- [ ] 监控Redis内存使用量
- [ ] 添加告警规则（如响应时间 > 1s）
**预计耗时**: 4-5小时

## P3 - 长期优化（技术债务）

### 12. 数据持久化增强
**当前问题**: 只依赖Redis，数据可能丢失
**影响**: Redis故障时分支元数据丢失
**优化方案**:
- [ ] 添加PostgreSQL持久化层
- [ ] Redis作为缓存，PostgreSQL作为主存储
- [ ] 定期同步Redis到PostgreSQL
**预计耗时**: 6-8小时

### 13. 分支权限细化
**当前问题**: 只验证user_id，没有更细的权限控制
**影响**: 无法实现分支共享功能
**优化方案**:
- [ ] 添加分支可见性字段（private/public/shared）
- [ ] 支持多用户协作编辑
- [ ] 添加分支访问日志
**预计耗时**: 5-6小时

### 14. 分支导入导出
**当前问题**: 无法导出分支数据
**影响**: 用户无法备份或分享分支
**优化方案**:
- [ ] 支持导出分支为JSON文件
- [ ] 支持导入JSON文件恢复分支
- [ ] 支持分支克隆功能
**预计耗时**: 3-4小时
