## 🎯 核心功能概览

### 功能1：重开Session
清空当前对话历史，开始全新对话，避免上下文污染

**优先级**: P0
**预计工期**: 2-3小时

### 功能2：对话分支管理
在任意消息处创建分支，支持多条对话路径并存

**优先级**: P0
**预计工期**: 1-2天

### 功能3：分支可视化
树形展示对话分支结构，支持快速导航和切换

**优先级**: P1
**预计工期**: 2-3天

### 功能4：编辑即分支
编辑任意历史消息时自动创建新分支，保留原始内容

**优先级**: P1
**预计工期**: 1天

## 🔑 关键决策记录

### 决策1：采用"分支树"模式而非简单回滚
**原因**:
- 业界主流方案（ChatGPT、Claude、Vercel AI都采用此模式）
- 不丢失任何历史数据
- 用户体验更好

**参考**: `02_技术调研.md`

### 决策2：利用LangGraph的thread_id作为分支ID
**原因**:
- 无需修改LangGraph核心逻辑
- 每个分支是独立的thread_id
- Redis checkpoint自动管理状态

**参考**: `03_数据结构设计.md` 和 `04_数据库设计.md`

### 决策3：前端使用Zustand而非Redux
**原因**:
- 更轻量（<1KB）
- TypeScript友好
- 学习曲线低
- Bifrost AI等项目验证过

**参考**: `06_前端组件设计.md`
