## 🏆 项目1: Bifrost AI

### 项目信息
- **仓库**: https://github.com/sderosiaux/bifrost-ai
- **Stars**: ~1.2k
- **语言**: TypeScript (前端) + JavaScript (后端)
- **最后更新**: 2024年活跃

### 技术架构
```
前端: React 18 + TypeScript + Tailwind CSS + Zustand
后端: Node.js + Fastify + node-llama-cpp v3
模型: GPT-OSS 20B (本地运行)
```

### 核心实现：Conversation Branching

**1. 数据结构**
```typescript
interface Message {
  id: string;
  parentId: string | null;
  content: string;
  role: 'user' | 'assistant';
  timestamp: number;
  branchId: string;
}
```

**2. 状态管理（Zustand）**
```typescript
interface ConversationStore {
  messages: Map<string, Message>;
  currentBranchId: string;
  branches: Map<string, Branch>;

  createBranch: (messageId: string) => void;
  switchBranch: (branchId: string) => void;
  selectBranch: (branchId: string) => void;
}
```

**3. Time Travel实现**
- 通过`parentId`构建消息树
- 切换分支时重建消息列表
- 保留完整历史，不丢失数据

### 借鉴点
✅ **Zustand状态管理** - 简单高效，比Redux轻量
✅ **分支侧边栏UI** - 树形可视化，用户体验好
✅ **即时创建分支** - 点击即创建，无需额外步骤

### 不适用点
❌ 纯前端存储 - 不适合多设备同步
❌ 本地模型 - 我们使用云端API

**2. 树遍历算法**
```typescript
function getConversationPath(messageId: string): Message[] {
  const path = [];
  let current = messageId;

  while (current !== null) {
    const message = messagesMap.get(current);
    path.unshift(message);
    current = message.parentId;
  }

  return path;
}
```

**3. 分支注解系统**
- 每条消息必须有`parentId`
- 首条消息`parentId = null`
- 通过`buildAdjacency`构建邻接表

### 借鉴点

## 🏆 项目3: CustomGPT

### 项目信息
- **仓库**: https://github.com/JatSh1804/customGPT
- **Stars**: ~200
- **语言**: TypeScript + Python
- **技术栈**: Next.js + Supabase + PostgreSQL

### 核心设计：数据库三表模型

**1. 表结构**
```sql
-- 会话表
CREATE TABLE user_chats (
  id UUID PRIMARY KEY,
  user_id UUID,
  title TEXT,
  active_branch_id UUID,
  created_at TIMESTAMP
);

-- 分支表
CREATE TABLE user_chat_branches (
  id UUID PRIMARY KEY,
  chat_id UUID REFERENCES user_chats(id),
  parent_branch_id UUID,
  child_branch_ids UUID[],  -- PostgreSQL数组
  created_at TIMESTAMP
);

-- 消息表
CREATE TABLE branch_messages (
  id UUID PRIMARY KEY,
  branch_id UUID REFERENCES user_chat_branches(id),
  parent_message_id UUID,
  content JSONB,              -- 支持富文本
  role TEXT,
  created_at TIMESTAMP
);
```

**2. 递归查询**
```sql
-- 获取分支的完整消息树
WITH RECURSIVE message_tree AS (
  SELECT * FROM branch_messages WHERE parent_message_id IS NULL
  UNION ALL
  SELECT m.* FROM branch_messages m
  JOIN message_tree mt ON m.parent_message_id = mt.id
)
SELECT * FROM message_tree;
```

**3. 编辑即分支逻辑**
- 用户编辑任意消息 → 创建新分支
- 原分支完全保留
- 新分支从编辑点开始

### 借鉴点
✅ **三表设计** - 清晰的数据关系
✅ **JSONB灵活性** - 支持扩展字段
✅ **递归查询** - PostgreSQL原生支持

### 不适用点
⚠️ 需评估 - PostgreSQL vs Redis选择

## 📈 技术选型建议

### 后端存储方案对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|-----|------|--------|
| **Redis (LangGraph checkpoint)** | ✅ 已有基础设施<br>✅ 毫秒级性能<br>✅ 无需代码改动 | ⚠️ 7天TTL限制<br>⚠️ 不适合长期存储 | ⭐⭐⭐⭐⭐ |
| **PostgreSQL (三表)** | ✅ 永久存储<br>✅ 复杂查询<br>✅ 数据完整性 | ❌ 需要新建表<br>❌ 响应较慢 | ⭐⭐⭐⭐ |
| **混合方案** | ✅ 结合两者优点<br>✅ 灵活性强 | ⚠️ 实现复杂度高 | ⭐⭐⭐ |

**最终选择**: **Redis为主 + PostgreSQL为辅（可选）**

理由：
1. LangGraph已使用Redis checkpoint，天然支持多thread_id（分支）
2. 每个分支就是一个独立的thread_id，无需重构
3. 分支元数据（名称、时间）用Redis Hash存储
4. 如需长期存储，后期可迁移到PostgreSQL

## 💡 核心技术决策

### 决策1: 使用LangGraph的thread_id作为分支ID

**论证**:
- LangGraph已支持多thread_id
- 每个thread_id是独立的checkpoint序列
- Redis自动管理状态持久化
- **无需修改LangGraph核心代码**

**实现**:
```python
# 主分支
main_thread_id = "conv_12345"

# 创建分支
branch_thread_id = f"{main_thread_id}:branch:{uuid.uuid4()}"

# LangGraph自动处理
config = {"configurable": {"thread_id": branch_thread_id}}
```

### 决策2: 分支元数据用Redis Hash

**论证**:
- 快速查询所有分支
- 支持原子更新
- 与checkpoint数据分离

**实现**:
```python
# 存储分支元数据
redis.hset(
    f"conversation_branches:{conv_id}",
    branch_id,
    json.dumps({
        "name": "探索方案A",
        "parent_message_id": "msg_789",
        "created_at": "2025-11-07T10:30:00Z"
    })
)
```

### 决策3: 前端使用消息树数据结构

**论证**:
- 符合业界标准（Vercel AI等）
- 支持高效遍历和查询
- 易于可视化展示

**实现**:
```typescript
interface MessageTree {
  nodes: Map<string, MessageNode>;
  adjacencyList: Map<string, string[]>;

  getPath(messageId: string): MessageNode[];
  getSiblings(messageId: string): MessageNode[];
  findLeaves(): MessageNode[];
}
```

## ✅ 技术调研结论

### 可行性评估
✅ **技术可行** - 有多个成熟案例
✅ **架构兼容** - 与现有LangGraph无缝集成
✅ **性能可控** - Redis毫秒级响应
✅ **开发成本** - 预计1-2周完成核心功能

### 风险评估
⚠️ **中风险**: LangGraph checkpoint API变更
⚠️ **低风险**: Redis存储容量限制
⚠️ **低风险**: 前端性能（大量分支时）

### 推荐方案
**Phase 1**: 基于LangGraph thread_id实现基础分支
**Phase 2**: 添加Zustand状态管理和UI可视化
**Phase 3**: 引入PostgreSQL长期存储（可选）
