## 🎯 功能概述

### Add to Chat - 快速发送到AI助手

**核心价值：** 将编辑器中选中的文本快速发送到AI助手对话框，建立编辑器与AI助手的无缝连接。

**使用场景：**
- 用户在编辑器中选中一段文字
- 点击"Add to Chat"按钮
- 自动打开右侧Agent聊天面板
- 文本作为上下文传递给AI助手
- 用户可以自由输入提示词进行各种操作

**关键特性：**
- ✅ 无缝上下文传递
- ✅ 自动打开侧边栏
- ✅ 支持长文本处理
- ✅ 保持写作流程

---

### Quick Edit - 编辑器内AI对话

**核心价值：** 在编辑器内直接弹出迷你AI对话框，无需切换到侧边栏，保持高度专注的写作体验。

**使用场景：**
- 用户在编辑器中选中一段文字
- 点击"Quick Edit"按钮
- 在选中文字附近直接弹出浮动对话框
- 用户输入提示词与AI交互
- AI响应直接显示在浮动框中
- 一键应用到编辑器或关闭

**关键特性：**
- ✅ 编辑器内浮动UI
- ✅ 不打断写作流
- ✅ 快速AI交互
- ✅ 实时预览
- ✅ 支持流式输出

## 🔑 核心区别对比

| 特性 | Add to Chat | Quick Edit |
|------|-------------|------------|
| **交互位置** | Agent 侧边栏（右侧面板） | 编辑器内浮动框 |
| **使用API** | `/api/v1/agent/chat/stream` | `/api/v1/ai/complete` |
| **UI形态** | 引用块 + 输入框 | 轻量级浮动窗口 |
| **文字展示** | 引用块（输入框保持空白） | 浮动框内显示 |
| **上下文切换** | 需要切换到侧边栏 | 无需切换，停留在编辑器 |
| **适用场景** | 复杂操作、多轮对话 | 快速、单次操作 |
| **速度** | 稍慢（需要打开侧边栏） | 很快（即时弹出） |
| **对话能力** | 完整 Agent 能力 | AI续写能力（可自定义prompt） |
| **快捷键** | Ctrl+Shift+A | Ctrl+E |
| **实现复杂度** | 中等（引用块 + 状态传递） | 较高（浮动UI + 定位） |
| **✨ 技术依赖** | **无（开箱即用）** | **需先修复AIService** |

## 📊 现有系统分析

### ✅ **Add to Chat：开箱即用**

**使用API：** `/api/v1/agent/chat/stream`

**API特点：**
- ✅ 完整的Agent对话能力
- ✅ 原生支持任意用户消息
- ✅ 请求格式：`{ message: string, work_id?: string, chapter_id?: string, ... }`
- ✅ 无需任何修改，立即可用

**实现文件：**
- 后端：`backend/app/api/v1/agent.py:865-1179`
- 前端：`src/services/agentApi.ts`

**结论：** ✅ **Add to Chat可以立即开始开发，无需等待任何准备工作**

---

### ⚠️ **Quick Edit：需要修复AIService**

**使用API：** `/api/v1/ai/complete`

**问题描述：**
- ✅ 后端API已经支持自定义prompt（通过 `prompt` 参数）
- ❌ 前端 `AIService.ts` (第196-201行) 将 `prompt` 参数**写死为 `'续写'`**
- ❌ 导致Quick Edit无法使用自定义提示词功能

**影响范围：**
- ❌ **只影响Quick Edit功能**
- ✅ Add to Chat不受影响（使用不同的API）

**解决方案：**
详见 [04_前后端协作方案_v1.1修订版.md](./04_前后端协作方案_v1.1修订版.md)，预计1-2天即可完成修复。

## ⚠️ 技术挑战与风险

### 挑战1：状态同步
**问题：** 编辑器、浮动框、侧边栏三者之间的状态同步

**解决方案：**
- 使用Zustand集中管理状态
- 定义清晰的状态更新流程
- 避免循环依赖

---

### 挑战2：浮动UI定位
**问题：** Quick Edit浮动框的精准定位和自适应

**解决方案：**
- 使用@floating-ui/dom库
- 处理边界情况（滚动、窗口调整）
- 智能定位算法

---

### 挑战3：性能优化
**问题：** 频繁的AI调用可能影响性能

**解决方案：**
- 请求防抖
- 取消机制
- 流式响应优化
- 大文本分块处理

---

### 挑战4：用户体验
**问题：** 功能过多可能导致用户混淆

**解决方案：**
- 清晰的视觉区分
- 首次使用引导
- 快捷键提示
- 简洁的交互设计
