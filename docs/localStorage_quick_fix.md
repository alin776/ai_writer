# localStorage 配额问题 - 快速解决指南

## 🚨 问题现象

- 刷新页面后自动退出登录
- 历史记录丢失
- 浏览器控制台出现存储配额错误

## ✅ 已实施的解决方案

### 1. 智能压缩（自动生效）

系统会自动检测 localStorage 使用情况：
- **使用率 < 50%**: 不压缩，保持完整数据
- **使用率 50-80%**: 轻度压缩，移除冗余数据
- **使用率 > 80%**: 重度压缩，只保留关键信息

### 2. 会话数量限制（已生效）

- **旧版本**: 保留 10 个会话（可能占用 5-10MB）
- **新版本**: 保留 3 个会话（占用 150-300KB）
- 超过 3 个的旧会话自动删除

### 3. 错误提示（已生效）

当存储空间不足时，会显示友好提示：
```
存储空间不足：认证信息无法保存，刷新页面可能需要重新登录。
请清理浏览器缓存后重试。
```

## 🛠️ 立即清理（推荐）

### 方法 1：使用开发者工具（最快）

1. 按 `F12` 打开浏览器开发者工具
2. 切换到 **Console** 标签
3. 输入以下命令并回车：

```javascript
// 查看当前存储使用情况
storageDebug.print()

// 自动清理（释放空间）
storageDebug.cleanup()
```

### 方法 3：清除浏览器缓存

#### Chrome / Edge:
1. 按 `Ctrl + Shift + Delete`
2. 选择"Cookie 和其他网站数据"
3. 时间范围选择"全部时间"
4. 点击"清除数据"
5. 重新登录应用

#### Firefox:
1. 按 `Ctrl + Shift + Delete`
2. 选择"Cookie"和"网站数据"
3. 时间范围选择"全部"
4. 点击"立即清除"
5. 重新登录应用

## 🔬 技术细节

### 数据压缩策略

**Explore 工具结果**:
- 原始: 包含完整检索结果（可能 100+ 条，每条几 KB）
- 压缩: 只保留前 3 条摘要（标题 + 分数）
- 节省: ~95%

**工具调用参数**:
- 原始: 所有参数
- 压缩: 只保留关键参数（query, type, limit）
- 节省: ~70%

**长文本内容**:
- 原始: 完整内容
- 压缩: 截断到 500-1000 字符
- 节省: ~80%

**历史会话**:
- 原始: 包含完整 flowItems
- 压缩: 完全移除 flowItems
- 节省: ~90%

### 效果预估

| 场景 | 原始大小 | 压缩后 | 节省 |
|------|---------|--------|------|
| 单个会话 | 500 KB | 50 KB | 90% |
| 3 个会话 | 1.5 MB | 150 KB | 90% |
| 10 个会话 | 5 MB | 500 KB | 90% |

## ❓ 常见问题

### Q: 压缩会影响功能吗？

**A**: 不会。压缩只移除冗余数据，保留所有关键信息：
- 消息内容完整保留
- 对话历史完整保留
- 执行轨迹的关键信息保留
- 只移除详细的检索结果和工具参数

### Q: 我的历史会话还能查看吗？

**A**: 可以。历史会话的消息内容和标题都完整保留，只是执行轨迹的详细信息被压缩了。如果需要查看详细的执行过程，可以在当前会话中查看。

### Q: 压缩是自动的吗？

**A**: 是的。系统会自动检测存储使用率并应用适当的压缩策略：
- 使用率低时不压缩
- 使用率高时自动压缩
- 完全透明，无需用户干预

### Q: 如果还是出现配额错误怎么办？

**A**: 按以下顺序尝试：
1. 运行 `storageDebug.cleanup()` 清理旧数据
2. 清除浏览器缓存
3. 如果问题持续，可能是其他应用占用了存储空间，需要清理其他网站的数据

### Q: 会话数量为什么限制为 3 个？

**A**: 基于以下考虑：
- 大多数用户只使用 1-2 个活跃会话
- 3 个会话足够满足日常需求
- 可以显著减少存储占用（从 5MB → 150KB）
- 如果需要更多历史，可以考虑后端存储方案

### Q: 如何恢复被删除的旧会话？

**A**: 抱歉，旧会话被自动删除后无法恢复。建议：
- 重要对话及时导出保存
- 考虑使用后端存储方案（未来功能）
