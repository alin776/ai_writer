# 当前实现分析

## 🏗️ 架构概览

项目采用**三阶段处理流程** + **双AI架构**：

```
输入文本
   ↓
阶段1: AI痕迹检测 (快速模型 - FastAIService)
   ↓
阶段2: 流式人性化改写 (标准模型 - HTTPAIService)
   ↓
阶段3: 效果验证 (快速模型 - FastAIService)
   ↓
输出结果
```

### 设计优势
- ✅ **职责分离**: 检测、改写、验证各司其职
- ✅ **成本优化**: 轻量任务用快速模型，核心任务用标准模型
- ✅ **流式输出**: 改写阶段支持实时反馈
- ✅ **灵活配置**: 各阶段可独立开关

async def detect_ai_traces(self, text: str) -> tuple[AIDetectionResult, dict]:
    """
    使用快速模型检测AI痕迹

    返回:
        - AIDetectionResult: 检测结果
        - dict: Token usage统计

### 技术细节

```python
async def humanize_stream(
    self,
    text: str,
    intensity: Literal["light", "medium", "strong"] = "medium"
) -> AsyncGenerator[tuple[str, dict | None], None]:
    """
    流式人性化改写

    Yields:
        (文本片段, usage或None)
        - 仅最后一个chunk带usage统计
    """
    # 1. 获取改写prompt
    humanize_prompt = get_humanize_prompt(text, intensity)

    # 2. 流式调用标准AI服务
    async for chunk, usage in self.ai_service._stream_chat(
        messages=[...],
        max_tokens=self.config.get_rewrite_max_tokens(len(text)),
        temperature=self.config.get_rewrite_temperature(intensity)
    ):
        yield chunk, usage
```

### 改写强度

| 强度 | 改动比例 | 温度 | 说明 |
|-----|---------|------|------|
| **light** | ~5% | 0.5 | 仅修改最明显的AI痕迹 |
| **medium** | 15-20% | 0.7 | 平衡自然度与内容保留 |
| **strong** | 30-40% | 0.9 | 最大化自然度 |

### 动态Token限制
`backend/app/core/humanize_config.py:41-59`

```python
def get_rewrite_max_tokens(self, text_length: int) -> int:
    """
    根据原文长度动态计算

    公式: 原文字符数 × 1.5 × 2
    """
    estimated_tokens = int(text_length * 1.5 * 2)
    return max(500, min(estimated_tokens, 4000))  # 500-4000之间
```

## ✨ 优点总结

1. **架构清晰** - 三阶段流程易理解、易维护
2. **成本优化** - 双AI架构平衡质量与成本
3. **流式输出** - 用户体验好
4. **数据完善** - 完整的会话记录与统计
5. **配置灵活** - 各阶段可独立控制
6. **错误处理** - Fallback机制健壮

---

## ⚠️ 不足之处

1. **检测维度少** - 只有3个维度（详见[问题与缺陷](./03-问题与缺陷.md)）
2. **Prompt简单** - 缺少具体指导
3. **无NLP预处理** - 完全依赖LLM
4. **无分段处理** - 长文本效果差
5. **无真实验证** - 未集成GPTZero等检测工具

详细分析请参阅 [问题与缺陷文档](./03-问题与缺陷.md)。
