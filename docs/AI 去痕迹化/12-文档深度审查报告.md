### 问题3: 中文NLP库可行性高估 🔴

#### 发现

**文档05-改进方案.md:244-279** 和 **文档10:77-94**:
```python
import jieba
import jieba.posseg as pseg
from synonyms import nearby  # ← 问题库

class ChineseTextRewriter:
    def _synonym_replacement(self, text: str) -> str:
        """同义词替换"""
        words = pseg.cut(text)
        result = []

        for word, flag in words:
            if flag in ['a', 'd']:  # 形容词和副词
                syns = nearby(word)  # ← 过于理想化
                if syns and len(syns[0]) > 0:
                    result.append(syns[0][0])
```

#### 实际问题

**synonyms库的限制**:

1. **词库有限**:
   ```python
   >>> from synonyms import nearby
   >>> nearby("当然")
   ([], [])  # ← 空结果！

   >>> nearby("首先")
   ([], [])  # ← 空结果！
   ```

2. **AI痕迹词覆盖率极低**:
   - "当然"、"首先"、"值得注意的是" 等AI套话大多无同义词
   - 文档承诺的"快速去除AI痕迹"无法实现

3. **性能问题**:
   ```python
   >>> import time
   >>> start = time.time()
   >>> nearby("漂亮")  # 需要加载540MB词向量模型
   >>> print(time.time() - start)
   3.2秒  # ← 首次加载很慢！
   ```

#### 影响

- ❌ **改进方案不可行**: 文档承诺的+20%效果无法达成
- ❌ **误导开发者**: 可能浪费时间实现无效功能
- ❌ **成本评估错误**: "零成本"实际上需要3-4GB内存

#### 修正建议

**方案A**: 改用规则替换（推荐）
```python
# 不依赖synonyms，使用规则库
AI_PATTERNS = {
    "当然": "",
    "首先，": "",
    "值得注意的是": "要注意",
    # ... 50+规则
}

def preprocess(text):
    for pattern, replacement in AI_PATTERNS.items():
        text = text.replace(pattern, replacement)
    return text
```

**方案B**: 使用更好的中文同义词库
```python
# 考虑使用其他库或API
from wordvector import similar_words  # 示例
from thesaurus_api import get_synonyms  # 示例
```

### 问题5: Token计算公式不准确 🔴

#### 发现

**文档02-当前实现分析.md:203-213**:
```python
def get_rewrite_max_tokens(self, text_length: int) -> int:
    """
    根据原文长度动态计算

    公式: 原文字符数 × 1.5 × 2
    """
    estimated_tokens = int(text_length * 1.5 * 2)
    return max(500, min(estimated_tokens, 4000))
```

**实际代码** (humanize_config.py:41-59):
```python
def get_rewrite_max_tokens(self, text_length: int) -> int:
    """
    根据原文长度动态计算改写的最大token数

    Args:
        text_length: 原文长度(字符数)

    Returns:
        最大token数
    """
    # 经验公式: 改写后文本长度约为原文的1.2-2倍
    # 1个中文字符约等于1.5个token
    estimated_tokens = int(text_length * 1.5 * 2)

    # 设置上下限
    min_tokens = 500
    max_tokens = 4000

    return max(min_tokens, min(estimated_tokens, max_tokens))
```

**实际API使用** (humanize.py:395-396):
```python
if total_tokens == 0:
    text_length = len(request.text)
    total_tokens = int(text_length * 1.5 * 3)  # ← 注意这里是×3！
    logger.warning(f"未获取到实际token消耗,使用估算值: {total_tokens}")
```

#### 矛盾分析

- ❌ 文档说公式是 `text_length × 1.5 × 2`
- ❌ API实际使用 `text_length × 1.5 × 3`
- ❌ 两处不一致，导致成本估算偏差

#### 影响

- **成本估算不准**: 实际成本可能比文档高50%
- **用户预期偏差**: 用户看到的token消耗与文档不符

#### 修正建议

统一公式并在文档中说明：
```python
# 统一使用
total_tokens = int(text_length * 1.5 * 2.5)  # 折中值

# 或分阶段说明
detection_tokens = int(text_length * 1.5)
rewrite_tokens = int(text_length * 1.5 * 2)
verification_tokens = int(text_length * 1.5 * 0.5)
total_tokens = detection_tokens + rewrite_tokens + verification_tokens
```
