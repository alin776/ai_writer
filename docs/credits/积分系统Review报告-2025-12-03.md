## 2. 新发现问题清单

### 🔴 High Priority (1个)

#### 问题H1: InvitationUsage.invitee_id缺少唯一约束

**文件**: `backend/app/models/invitation_usage.py:22-27`
**严重程度**: High
**问题类型**: 数据一致性

**问题描述**:
`invitee_id` 字段只有索引,缺少 `unique=True` 约束,允许同一用户被多次邀请记录。

**当前代码**:
```python
invitee_id = Column(
    UUID(as_uuid=True),
    ForeignKey("users.id", ondelete="CASCADE"),
    nullable=False,
    index=True  # ❌ 缺少 unique=True
)
```

**影响范围**:
- 同一用户可能有多条邀请使用记录
- 邀请统计可能不准确
- 激活逻辑可能重复触发

**修复建议**:
```python
invitee_id = Column(
    UUID(as_uuid=True),
    ForeignKey("users.id", ondelete="CASCADE"),
    nullable=False,
    unique=True,  # ✅ 添加唯一约束
    index=True
)
```

**修复优先级**: High
**预计工作量**: 0.5小时 (需要生成迁移文件)

        CheckConstraint('total_consumed >= 0', name='check_consumed_non_negative'),
        CheckConstraint('total_gifted >= 0', name='check_gifted_non_negative'),
    )

#### 问题M3: AI调用预检查与扣费时间窗口

**文件**: `backend/app/services/ai/http_ai_service.py:158-216, 920-1028`
**严重程度**: Medium
**问题类型**: 并发安全

**问题描述**:
预检查和实际扣费之间存在时间窗口,用户可能在此期间消费积分,导致扣费失败。

**影响范围**:
- 预检查通过但实际扣费失败
- 用户体验不佳(AI调用到一半提示余额不足)

**修复建议** (3种方案):

**方案A: 预扣费机制** (推荐,但复杂度高)
1. 预检查时先扣除估算积分(标记为"预扣费")
2. AI调用成功后,根据实际usage多退少补
3. AI调用失败时,全额退款

**方案B: 乐观锁机制** (中等复杂度)
1. 预检查时记录余额版本号
2. 实际扣费时检查版本号是否变化
3. 变化则重新检查余额

**方案C: 接受现状** (当前)
1. 实际扣费时会抛出异常
2. 用户能感知错误
3. 代价: 用户体验不佳

**修复优先级**: Medium
**预计工作量**: 方案A: 4-6小时, 方案B: 2-3小时
