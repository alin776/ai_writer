# AI Writer 数据库 ER 图

> 数据库采用 PostgreSQL,使用 SQLAlchemy ORM

## 数据库概览

数据库共有 **8 个核心表**,分为 4 大模块:
- **用户模块**: users (用户表)
- **作品模块**: works (作品), chapters (章节), worldviews (世界观)
- **AI 模块**: rewrite_sessions (改写会话), rewrite_results (改写结果)
- **知识库模块**: knowledge_bases (知识库), knowledge_items (知识条目)

---

## 1. 数据库整体关系

```mermaid
erDiagram
    USERS ||--o{ WORKS : "创作"
    USERS ||--o{ REWRITE_SESSIONS : "使用"
    USERS ||--o{ KNOWLEDGE_BASES : "拥有"

    WORKS ||--o{ CHAPTERS : "包含"
    WORKS ||--o{ WORLDVIEWS : "设定"

    REWRITE_SESSIONS ||--o{ REWRITE_RESULTS : "产生"

    KNOWLEDGE_BASES ||--o{ KNOWLEDGE_ITEMS : "包含"
```

**关系说明**:
- **用户 → 作品**: 一对多 (一个用户可以创作多个作品)
- **用户 → 改写会话**: 一对多 (一个用户有多次改写历史)
- **用户 → 知识库**: 一对多 (一个用户可以有多个知识库)
- **作品 → 章节**: 一对多 (一个作品包含多个章节)
- **作品 → 世界观**: 一对多 (一个作品有多个世界观设定)
- **改写会话 → 改写结果**: 一对多 (一次会话产生多个模型结果)
- **知识库 → 知识条目**: 一对多 (一个知识库包含多个条目)

## 2. 用户模块 - users 表

```mermaid
erDiagram
    USERS {
        uuid id PK "主键"
        varchar username UK "用户名"
        varchar email UK "邮箱"
        varchar hashed_password "密码哈希"
        varchar full_name "真实姓名"
        varchar avatar "头像URL"
        text bio "个人简介"
        boolean is_active "是否激活"
        boolean is_admin "是否管理员"
        boolean is_verified "是否验证"
        timestamp created_at "创建时间"
        timestamp updated_at "更新时间"
        timestamp last_login_at "最后登录"
    }
```

**表说明**:
- **用途**: 存储用户账号和个人信息
- **主键**: UUID,自动生成
- **唯一约束**: username, email

**关键字段**:
- `username`: 用户名,3-50 字符,唯一
- `email`: 邮箱,可选,唯一
- `hashed_password`: bcrypt 加密的密码
- `is_active`: 账号是否激活 (默认 true)
- `is_admin`: 是否管理员 (默认 false)
- `is_verified`: 邮箱是否验证 (默认 false)

**索引**:
- PRIMARY KEY (id)
- UNIQUE INDEX (username)
- UNIQUE INDEX (email)

**关系**:
- 一对多: users → works
- 一对多: users → rewrite_sessions
- 一对多: users → knowledge_bases

## 3. 作品模块 - works 表

```mermaid
erDiagram
    WORKS {
        uuid id PK "主键"
        uuid author_id FK "作者ID"
        varchar title "作品标题"
        text description "作品简介"
        varchar cover_image "封面图"
        enum genre "作品类型"
        enum status "作品状态"
        integer total_words "总字数"
        integer total_chapters "总章节数"
        integer view_count "浏览次数"
        timestamp created_at "创建时间"
        timestamp updated_at "更新时间"
        timestamp published_at "发布时间"
    }
```

**表说明**:
- **用途**: 存储小说作品基本信息
- **外键**: author_id → users(id)

**关键字段**:
- `title`: 作品标题,1-200 字符
- `genre`: 作品类型枚举
- `status`: 作品状态枚举
- `total_words`: 总字数,自动统计
- `total_chapters`: 总章节数,自动统计
- `view_count`: 浏览次数

**枚举类型**:

### genre (作品类型)
- `fantasy` - 玄幻
- `urban` - 都市
- `romance` - 言情
- `scifi` - 科幻
- `wuxia` - 武侠
- `history` - 历史
- `game` - 游戏
- `other` - 其他

### status (作品状态)
- `draft` - 草稿
- `writing` - 连载中
- `completed` - 已完结
- `abandoned` - 已弃坑

**索引**:
- PRIMARY KEY (id)
- INDEX (author_id)
- INDEX (title)

**级联删除**: 删除作品时自动删除所有章节和世界观

## 4. 作品模块 - chapters 表

```mermaid
erDiagram
    CHAPTERS {
        uuid id PK "主键"
        uuid work_id FK "作品ID"
        varchar title "章节标题"
        text content "章节内容"
        integer order "章节顺序"
        boolean is_published "是否发布"
        integer word_count "字数"
        integer view_count "浏览次数"
        timestamp created_at "创建时间"
        timestamp updated_at "更新时间"
        timestamp published_at "发布时间"
    }
```

**表说明**:
- **用途**: 存储作品的章节内容
- **外键**: work_id → works(id)

**关键字段**:
- `title`: 章节标题,1-200 字符
- `content`: 章节正文内容
- `order`: 章节排序号
- `is_published`: 是否发布 (默认 false)
- `word_count`: 字数,自动计算

**索引**:
- PRIMARY KEY (id)
- INDEX (work_id)
- INDEX (order)

**触发器**:
- 创建/更新/删除章节时自动更新 works 表的 total_words 和 total_chapters

## 6. AI 模块 - rewrite_sessions 表

```mermaid
erDiagram
    REWRITE_SESSIONS {
        uuid id PK "主键"
        uuid user_id FK "用户ID"
        text original_text "原文"
        text context_before "前文"
        text context_after "后文"
        varchar mode "改写模式"
        text custom_requirement "自定义要求"
        timestamp created_at "创建时间"
    }
```

**表说明**:
- **用途**: 记录 AI 改写助手的使用历史
- **外键**: user_id → users(id)

**关键字段**:
- `original_text`: 待改写的原文
- `context_before`: 前文上下文
- `context_after`: 后文上下文
- `mode`: 改写模式 (optimize/expand/compress/custom)
- `custom_requirement`: 自定义改写要求

**mode 枚举**:
- `optimize` - 优化提升
- `expand` - 扩写丰富
- `compress` - 精简压缩
- `custom` - 自定义

**索引**:
- PRIMARY KEY (id)
- INDEX (user_id)
- INDEX (created_at)

**级联删除**: 删除会话时自动删除所有改写结果

## 7. AI 模块 - rewrite_results 表

    }

**表说明**:
- **用途**: 存储每个 AI 模型的改写结果
- **外键**: session_id → rewrite_sessions(id)

**关键字段**:
- `model_name`: AI 模型名称 (gemini-2.5-pro, gpt-4 等)
- `rewritten_text`: 改写后的文本
- `word_count`: 改写后字数
- `elapsed_time`: AI 处理耗时(秒)
- `error`: 错误信息 (失败时记录)
- `is_selected`: 用户是否选择此结果

**索引**:
- PRIMARY KEY (id)
- INDEX (session_id)
- INDEX (created_at)

## 16. 查询优化建议

```mermaid
graph TB
    A[查询优化] --> B[使用连接查询]
    A --> C[避免N+1问题]
    A --> D[使用索引覆盖]
    A --> E[分页查询]

    B --> B1[JOIN代替多次查询]
    C --> C1[使用子查询]
    C --> C2[预加载关联数据]
    D --> D1[只查询需要的字段]
    E --> E1[LIMIT + OFFSET]

    style A fill:#fff3e0
    style B fill:#e8f5e9
    style C fill:#e1bee7
    style D fill:#bbdefb
    style E fill:#ffccbc
```

**优化技巧**:

### 1. 使用连接查询
```sql
-- 好: 一次查询
SELECT w.*, u.username
FROM works w
JOIN users u ON w.author_id = u.id;

-- 差: 多次查询
SELECT * FROM works;
-- 然后对每个 work 查询 user
```

### 2. 避免 N+1 问题
```python
# SQLAlchemy 使用 joinedload
works = db.query(Work).options(
    joinedload(Work.author),
    joinedload(Work.chapters)
).all()
```

### 3. 使用索引覆盖
```sql
-- 好: 只查询需要的字段
SELECT id, title FROM works WHERE author_id = '...';

-- 差: 查询所有字段
SELECT * FROM works WHERE author_id = '...';
```

### 4. 分页查询
```sql
SELECT * FROM works
ORDER BY created_at DESC
LIMIT 20 OFFSET 0;
```

**备份命令**:
```bash
# 完整备份
pg_dump -U novelaide -d novelaide > backup_$(date +%Y%m%d).sql

# 仅备份数据
pg_dump -U novelaide -d novelaide --data-only > data_backup.sql

# 仅备份结构
pg_dump -U novelaide -d novelaide --schema-only > schema_backup.sql
```

**恢复命令**:
```bash
# 恢复完整备份
psql -U novelaide -d novelaide < backup.sql

# 恢复数据
psql -U novelaide -d novelaide < data_backup.sql
```

**清空数据**:
