# SSE 心跳保活修复小结

## 问题现象

AI 对话功能在长时间思考（>100 秒无输出）时，前端反复出现 "network error"，对话中断、内容丢失，用户体验严重受损。

## 根因分析

Cloudflare 代理对 HTTP 长连接有约 100 秒的空闲超时机制。AI 在"思考"阶段不产生任何 SSE 数据，Cloudflare 判定连接已死并主动断开，导致前端收到网络错误。问题本质不在前后端代码，而在中间代理层的超时策略。

## 尝试过的方案

直接在 SSE 流中注入周期性心跳注释是业界标准做法，方案一次命中。核心设计选择是用 `asyncio.Queue` + 双后台任务（事件生产者 + 心跳生产者）替代原来的直接 `async for` 迭代，这样在两次 event 之间的空窗期也能持续输出数据。

## 最终修复方法

只改了 1 个文件 `backend/app/api/v1/agent.py`，前端零改动。将原来的 `async for event in agent.astream_events(...)` 循环重构为：创建 asyncio.Queue，启动事件生产者任务和心跳生产者任务（每 15 秒注入哨兵），主生成器从队列消费，遇到心跳哨兵就 `yield ": heartbeat\n\n"`（SSE 注释行），遇到正常事件则走原有处理逻辑不变。`finally` 块中取消并 `await` 两个后台任务，确保客户端断连时无任务泄漏。前端 `agentApi.ts` 的 `if (!line.startsWith('data: ')) return` 天然过滤注释行，无需任何适配。

## 回归测试点

1. 正常对话流程：AI 回复内容完整显示，无丢失、无重复
2. 长时间思考场景：DevTools EventStream 中每 15 秒可见 `: heartbeat` 注释行
3. 前端静默过滤：心跳行不出现在 UI 中，不触发任何前端逻辑
4. 客户端断连：关闭浏览器标签后，后端任务正常清理，无泄漏
5. Agent 异���：后端报错时，error 事件正常发送到前端，心跳任务正常终止
6. Skill 切换 / buffer revision：原有的 skill_switched 事件和实时 revision 推送不受影响

| 优先级 | 项目 | 说明 |
|--------|------|------|
| P2 | 心跳间隔可配置化 | 当前硬编码 15 秒，可提取到环境变量或配置文件，便于不同部署环境调优 |
| P3 | 前端心跳监测 | 前端可利用心跳做连接健康检测：若超过 N 秒未收到任何数据（含心跳），主动提示用户连接可能异常 |
| P3 | 服务端心跳日志 | 在 debug 模式下记录心跳发送次数，辅助排查生产环境的连接问题 |
