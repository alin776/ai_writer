# Planning vs ReAct vs Multi-Agent 模式对比

> 文档版本: 1.0
> 创建日期: 2025-12-06
> 状态: 决策参考

---

## 概述

本文档对比分析三种Agent执行模式，为架构决策提供依据。

---

## 模式定义

### Planning 模式

```
阶段1: 规划 → 生成任务列表JSON（约2-3秒）
阶段2: 执行 → 并行执行任务（支持超时、进度回调）
阶段3: 总结 → 生成最终响应
```

**核心思想**: 先规划再执行

**当前实现状态**: ✅ 完整实现

### ReAct 模式

```
Thought → Action → Observation → Thought → Action → ... → 完成
```

**核心思想**: 边思考边执行

**当前实现状态**: ❌ 名存实亡（详见 01-react-mode-review.md）

### Multi-Agent 模式

```
大纲师 → 主笔 → 角色守护 → 逻辑审计 → 总编 → 定稿
```

**核心思想**: 分工 + 多重校验 + 外挂记忆

**当前实现状态**: 🆕 待实现

## 多维度对比

### 基础对比

| 维度 | Planning | ReAct | Multi-Agent |
|------|----------|-------|-------------|
| 核心思想 | 先规划再执行 | 边思考边执行 | 分工+多重校验 |
| 执行模式 | 顺序/并行 | 循环迭代 | 流水线 |
| 质量保证 | 单次执行 | 依赖模型 | 多重校验 |
| 长期记忆 | 有限 | 无 | 向量库+摘要链 |
| 人设一致性 | ❌ 不保证 | ❌ 不保证 | ✅ 专门Agent守护 |

### 写作场景适用性

| 场景 | Planning | ReAct | Multi-Agent |
|------|----------|-------|-------------|
| "帮我写第三章" | ✅ 适合 | ⚠️ 一般 | ✅ 最适合 |
| "继续写下去" | ✅ 适合 | ✅ 适合 | ✅ 适合 |
| 长篇连续写作 | ⚠️ 会遗忘 | ❌ 不适合 | ✅ 专门设计 |
| 人设一致性要求 | ❌ 无保证 | ❌ 无保证 | ✅ 角色守护 |
| 剧情逻辑校验 | ❌ 无 | ❌ 无 | ✅ 逻辑审计 |

### 技术对比

| 维度 | Planning | ReAct | Multi-Agent |
|------|----------|-------|-------------|
| 实现复杂度 | 中 | 低-中 | 高 |
| 代码侵入性 | 已有 | 需修复 | 新增模块 |
| 可调试性 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐ |
| 进度可见性 | ⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐⭐ |
| Token消耗 | 中 | 低-中 | 高 |

## 写作场景分析

### 为什么 Multi-Agent 更适合写作？

#### 1. 长篇写作的核心痛点

> "写到3万字时角色一致性下降40%，到5万字AI开始'创造性遗忘'早期剧情"

这是单AI + 大上下文窗口无法解决的问题。

#### 2. Multi-Agent 如何解决

| 痛点 | 解决方案 |
|------|---------|
| 角色性格崩塌 | 角色守护Agent专门校验 |
| 配角死两次 | 逻辑审计Agent检查时间线 |
| 风格漂移 | 风格锚定Prompt + 周期校验 |
| 上下文遗忘 | 向量库 + 摘要链 + 设定文档 |

#### 3. 质量保证机制

```
主笔写初稿
    ↓
角色守护: "苏晚性格应该是外柔内刚，这里反应太软弱"
    ↓
逻辑审计: "老周是新来的管家，不应该知道密室秘密"
    ↓
总编裁决: 综合修改，输出定稿
```

## 决策建议

### 推荐方案：移除ReAct，实现Multi-Agent

| 选项 | 推荐度 | 理由 |
|------|-------|------|
| 保留ReAct，修复问题 | ⭐⭐ | ReAct不适合写作场景 |
| 移除ReAct，只保留Planning | ⭐⭐⭐ | 简化但缺少质量保证 |
| 移除ReAct，实现Multi-Agent | ⭐⭐⭐⭐⭐ | 最适合写作场景 |

### 实施路径

```
第1步: 移除ReAct模式（清理代码）
第2步: 保留Planning模式（用于简单任务）
第3步: 实现Multi-Agent模式（用于写作任务）
```
