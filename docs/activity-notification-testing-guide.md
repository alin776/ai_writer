# 活动通知功能测试指南

## 功能概述

本文档用于测试和验证活动通知创建、展示和数据传递的完整流程。

## 新增功能说明

### 1. 展示方式配置

在通知创建表单的"其他设置"部分，现在有两个可选的展示方式：

- **通知铃铛**：通知会在顶部导航栏的铃铛图标中显示
- **弹窗提醒**：用户登录后首次进入作品管理界面时自动弹出

**特点：**
- 必须至少选择一种展示方式（有验证）
- 可以同时选择���种方式
- 弹窗提醒仅在用户登录后首次显示（使用 sessionStorage 控制）

### 2. 活动配置数据传递

**提交时的数据结构：**
```typescript
{
  // 基础字段
  title: string;
  content: string;
  type: NotificationType;
  displayType: string[]; // ['notification', 'modal']

  // 活动特有字段（仅当 type === 'event' 时）
  activityType?: ActivityType;
  activityRules?: ActivityRules;
  validFrom?: string;
  validUntil?: string;
}
```

**数据验证点：**
1. 提交时 console 会输出 `📤 提交通知数据:` 查看完整数据
2. 编辑时 console 会输出 `📝 编辑通知数据:` 查看加载的数据
3. 确保 `activityType` 和 `activityRules` 正确包含在请求中

## 测试场景

### 场景 1: 创建邀请活动通知（带弹窗）

#### 步骤
1. 登录管理后台
2. 进入"通知管理"页面
3. 点击"创建通知"按钮
4. 填写表单：
   ```
   标题：邀请好友赢积分
   内容：邀请1位好友注册，双方各得积分奖励！
   通知类型：活动
   优先级：重要
   封面图片：上传一张活动封面
   ```

5. 配置活动：
   - 点击"展开配置"
   - 活动类型：邀请活动
   - 邀请者奖励：
     * 类型：积分
     * 数量：500
     * 名称：邀请奖励积分
   - 被邀请者奖励：
     * 类型：积分
     * 数量：300
     * 名称：新用户欢迎积分
   - 完成条件：完成首次任务
   - 活动开始时间：今天
   - 活动结束时间：7天后

6. 其他设置：
   ```
   展示方式：
     ☑️ 通知铃铛
     ☑️ 弹窗提醒
   目标用户：全部用户
   发布方式：立即发布
   ```

7. 点击"创建通知"

#### 预期结果
1. ✅ 通知创建成功
2. ✅ 浏览器控制台输出提交的数据，包含 `activityType: 'invitation'` 和完整的 `activityRules`
3. ✅ 通知列表中显示新创建的通知，状态为"已发布"

打开浏览器控制台（F12），查找日志：

## 常见问题排查

### 问题 1: 提交时 activityType 或 activityRules 为空

**排查步骤：**
1. 检查是否选择了活动类型（邀请活动/比赛活动/积分活动）
2. 查看控制台是否有 `📤 提交通知数据:` 日志
3. 确认 `formData.type === NotificationType.EVENT`
4. 检查 `handleSubmit` 函数中的数据组装逻辑

**解决方案：**
- 在选择"活动"类型后，必须点击"展开配置"并选择具体的活动类型
- 确保至少配置了一个奖励项

### 问题 2: 编辑时活动配置未加载

**排查步骤：**
1. 查看控制台 `📝 编辑通知数据:` 日志
2. 检查后端返回的通知数据是否包含 `activityType` 和 `activityRules`
3. 确认 `handleEdit` 函数正确提取了这些字段

**解决方案：**
- 检查后端 API 是否正确返回了活动配置数据
- 确认 TypeScript 类型定义中包含这些字段

### 问题 3: 弹窗不显示

**排查步骤：**
1. 检查通知的 `displayType` 是否包含 `'modal'`
2. 确认通知状态为"已发布"（非草稿）
3. 查看通知是否已被标记为已读
4. 检查 sessionStorage 中的 `activity_modal_shown` 标记

**解决方案：**
- 创建通知时确保勾选"弹窗提醒"
- 登出后重新登录以重置 session
- 在数据库中将通知的 `isRead` 改为 `false`

### 问题 4: 展示方式未保存

**排查步骤：**
1. 查看提交数据中的 `displayType` 字段
2. 确认至少选择了一种展示方式（有验证提示）
3. 检查复选框的 onChange 逻辑

**解决方案：**
- 确保在提交前至少勾选一个展示方式
- 如果看到红色提示"至少选择一种展示方式"，说明验证生效
