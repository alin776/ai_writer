# 01 - DeepAgent 概述

> 在 Planning 模式基础上，增强动态反思和重新规划能力

## 1. 背景

### 1.1 现有 Planning 模式的优势

当前项目的 **Planning 模式** 已经具备完整的任务管理能力：

```
用户消息 → Planning阶段 → Execution阶段 → Summarization阶段
            (AI分解任务)   (MultiAgent执行)   (整合结果)
```

**已有能力**：
- ✅ 任务规划（on_plan 事件）
- ✅ 任务进度追踪（task_start/task_done 事件）
- ✅ 多 Agent 协作（MultiAgentExecutor）
- ✅ 前端任务列表展示（TaskListPanel）
- ✅ 流式响应（SSE）

**局限**：
- ❌ 一次性规划，无法动态调整
- ❌ 执行过程缺乏反思机制
- ❌ 发现问题后无法重新规划

### 1.2 ReAct 模式的问题

经过深度 Review，发现 ReAct 模式存在严重问题：

| 问题 | 影响 |
|------|------|
| 前后端状态不一致 | 后端支持，前端已标记移除 |
| 双重 API 路由 | `/chat/stream?mode=react` 和 `/chat/react-stream` 并存 |
| 缺少任务管理 | 没有 plan/task_start/task_done 事件 |
| 改造工作量大 | 需要 8-13 天完整改造 |

**结论**：不推荐在 ReAct 基础上开发，应该扩展 Planning 模式。

### 1.3 Deep Agents 的启发

[Deep Agents](https://github.com/langchain-ai/deepagents) 的核心理念：

1. **think_tool（反思工具）**: 纯上下文工程，迫使 Agent 在关键节点评估进度
2. **动态规划**: 根据执行结果调整任务列表
3. **子代理隔离**: 复杂任务委派给专业子代理

## 2. 目标

在 Planning 模式基础上，添加 **DeepAgent** 能力：

| 能力 | 说明 | 实现方式 |
|------|------|----------|
| 动态反思 | 执行过程中评估进度 | `think_tool` |
| 重新规划 | 根据反思结果调整任务 | 动态更新 plan |
| 透明思考 | 向用户展示推理过程 | 反思事件 |

## 3. 两种模式对比

### 3.1 现有 Planning 模式

```
┌─────────────────────────────────────────────────────────────┐
│                    Planning 模式（现有）                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  用户消息                                                    │
│      │                                                      │
│      ▼                                                      │
│  ┌─────────┐    ┌─────────┐    ┌─────────┐                 │
│  │ Planning │───►│Execution│───►│ Summary │                 │
│  │ (规划)   │    │ (执行)  │    │ (总结)  │                 │
│  └─────────┘    └─────────┘    └─────────┘                 │
│      │              │              │                        │
│      ▼              ▼              ▼                        │
│   plan事件     task_start     content事件                    │
│   (任务列表)    task_done      (最终结果)                     │
│                (进度更新)                                    │
│                                                             │
│  特点：一次规划 → 批量执行 → 输出结果                          │
│  问题：无法根据执行结果调整计划                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 增强后的 DeepAgent 模式

```
┌─────────────────────────────────────────────────────────────┐
│                  DeepAgent 模式（扩展）                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  用户消息                                                    │
│      │                                                      │
│      ▼                                                      │
│  ┌─────────┐                                                │
│  │ Planning │  ◄────────────────────────┐                   │
│  │ (规划)   │                           │                   │
│  └─────────┘                            │                   │
│      │                                  │                   │
│      ▼                                  │                   │
│  ┌─────────┐    ┌─────────┐    ┌─────────┐                 │
│  │ Execute │───►│ Reflect │───►│ Replan? │                 │
│  │ (执行)  │    │ (反思)  │    │(重规划?)│                  │
│  └─────────┘    └─────────┘    └─────────┘                 │
│      │              │              │                        │
│      │              │         是   │   否                   │
│      │              │         ┌────┴────┐                   │
│      │              │         │         ▼                   │
│      │              │         │    ┌─────────┐             │
│      │              │         └───►│ Summary │             │
│      │              │              │ (总结)  │             │
│      ▼              ▼              └─────────┘             │
│  task_start    reflection事件        content事件             │
│  task_done     (反思内容)           (最终结果)               │
│                                                             │
│  特点：规划 → 执行 → 反思 → (可选)重规划 → 继续               │
│  优势：可以根据执行结果动态调整计划                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 能力对比

| 维度 | Planning 模式 | DeepAgent 模式 |
|------|---------------|----------------|
| **规划时机** | 开始时一次性规划 | 开始规划 + 可重规划 |
| **执行方式** | 批量执行 | 执行 + 反思循环 |
| **计划调整** | 固定执行 | 可根据反思调整 |
| **反思能力** | 无 | think_tool |
| **思考透明** | 无 | 展示反思过程 |
| **适用场景** | 结构化任务 | 探索性/复杂任务 |
| **前端复用** | - | 完全复用 |

## 4. 用户视角

### 4.1 Planning 模式体验（现有）

```
用户: 帮我写第三章

AI: 正在规划任务...
    ┌─────────────────────────────────┐
    │ 执行计划                    2/5 │
    ├─────────────────────────────────┤
    │ ● 分析章节上下文          1.2s │
    │ ◐ 生成章节大纲            ...  │
    │ ○ 撰写章节内容                 │
    │ ○ 校验角色一致性               │
    │ ○ 润色输出                     │
    └─────────────────────────────────┘

    (执行完成后输出结果)
```

### 4.2 DeepAgent 模式体验（增强）

```
用户: 帮我写第三章，要承接前面的伏笔

AI: 正在规划任务...
    ┌─────────────────────────────────┐
    │ 执行计划                    1/4 │
    ├─────────────────────────────────┤
    │ ◐ 分析前文伏笔            ...  │
    │ ○ 生成章节大纲                 │
    │ ○ 撰写章节内容                 │
    │ ○ 校验伏笔回收                 │
    └─────────────────────────────────┘

    💭 反思: 分析发现前文有3个主要伏笔：
       1. 神秘老者的身份（第一章埋下）
       2. 主角的特殊体质（第二章暗示）
       3. 血神宫的阴谋（多处暗线）

       但第3个伏笔信息不完整，需要重新分析...

    (动态调整计划)
    ┌─────────────────────────────────┐
    │ 执行计划                    2/5 │  ← 任务数量变化
    ├─────────────────────────────────┤
    │ ● 分析前文伏笔            2.1s │
    │ ◐ 深入分析血神宫线索      ...  │  ← 新增任务
    │ ○ 生成章节大纲                 │
    │ ○ 撰写章节内容                 │
    │ ○ 校验伏笔回收                 │
    └─────────────────────────────────┘
```

## 5. 核心价值

### 5.1 对用户

- **更智能的响应**：Agent 会根据情况动态调整策略
- **透明的思考过程**：通过反思事件展示 Agent 的推理
- **更好的复杂任务处理**：探索性任务不再需要多轮对话

### 5.2 对开发者

- **极低侵入性**：复用 Planning 模式 95% 的代码
- **渐进式增强**：MVP → 增强版 → 完整版 → 子代理
- **MVP 前端零改动**：复用现有 `task_progress` 事件

## 6. 实现范围

### Phase 1: MVP（2天）

- [ ] `think_tool` 工具 - 反思（纯上下文工程）
- [ ] 动态重规划 - 根据反思结果更新任务列表
- [ ] **复用 `task_progress` 事件** - 发送反思内容（前端零改动）
- [ ] 最大反思次数限制 - 防止无限循环

### Phase 2: 增强版（1天）

- [ ] plan 更新事件（`is_update` 字段）
- [ ] 前端适配 `is_update`（保留已完成任务状态）
- [ ] 测试重规划场景

### Phase 3: 完整版（可选，2天）

- [ ] 前端反思气泡组件
- [ ] 新增 `reflection` 事件（独立事件类型）
- [ ] 样式优化

### Phase 4: 子代理支持

- [ ] `task()` 工具 - 动态生成子代理
- [ ] 子代理上下文隔离
- [ ] 子代理结果整合
