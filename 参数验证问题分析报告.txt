API 参数验证问题深度分析报告
执行时间: 2025-11-12

=== 摘要 ===
通过深度探索 backend/app/api/v1/ 目录下的所有API文件，发现3个明显的参数验证问题和1个潜在的N+1问题。

=== 问题 1: 用户列表API缺失limit上限验证 ===
文件: backend/app/api/v1/users.py (第222-239行)
风险等级: 高

问题描述:
  @router.get("", response_model=List[UserResponse])
  async def get_users(
    skip: int = 0,           # 没有ge=0验证
    limit: int = 100,        # 没有le=xxx验证!
    search: str = None,      # 没有max_length验证
    ...
  ):

潜在风险:
  - DoS攻击: 设置limit=999999导致服务崩溃
  - 内存溢出: 一次性加载过多用户对象
  - 数据库超时: 大量查询堆积

建议修复:
  @router.get("", response_model=List[UserResponse])
  async def get_users(
    skip: int = Query(0, ge=0),
    limit: int = Query(20, ge=1, le=100),
    search: str = Query(None, max_length=100),
    ...
  ):

=== 问题 2: admin.get_users_growth中的N+1问题 ===
文件: backend/app/api/v1/admin.py (第163-203行)
风险等级: 高

问题描述:
  当days=90时,循环执行180次数据库查询(90个循环×2个查询):
  
  for i in range(days):  # days最大90
    users_count = await db.scalar(
      select(func.count(User.id)).where(User.created_at < day_end)
    )
    works_count = await db.scalar(
      select(func.count(Work.id)).where(Work.created_at < day_end)
    )

潜在风险:
  - 性能问题: 耗时可能30秒以上
  - 数据库连接池耗尽
  - API超时

建议修复:
  使用数据库时间分组替代循环,单一查询获取所有数据

=== 问题 3: review.get_chapter_tasks允许limit=500 ===
文件: backend/app/api/v1/review.py (第173-201行)
风险等级: 中

问题描述:
  limit: int = Query(100, ge=1, le=500)  # 允许一次返回500条
  
  相比项目其他API(通常20-100),这个限制过宽

潜在风险:
  - 中等DoS风险
  - 网络传输缓慢
  - 前端处理困难

建议修复:
  limit: int = Query(20, ge=1, le=100)

=== 问题 4: chapters.reorder_chapters缺数组长度验证 ===
文件: backend/app/api/v1/chapters.py (第195-228行)
风险等级: 中

问题描述:
  @router.post("/reorder", status_code=status.HTTP_200_OK)
  async def reorder_chapters(
    work_id: str = Body(...),
    chapter_ids: List[str] = Body(...),  # 没有长度限制!
    ...
  ):

潜在风险:
  - 内存溢出: 加载超大列表
  - 数据库锁定: 批量更新导致表级锁
  - 业务逻辑错误: 未验证列表完整性

建议修复:
  class ReorderChaptersRequest(BaseModel):
    work_id: str
    chapter_ids: List[str] = Field(..., min_items=1, max_items=1000)

=== 问题 5: monitoring.get_business_metrics参数无验证 ===
文件: backend/app/api/v1/monitoring.py (第54-65行)
风险等级: 低

问题描述:
  @router.get("/metrics/business")
  async def get_business_metrics(
    time_window_hours: int = 24  # 没有验证!
  ):

潜在风险:
  - 可以设置负数或0
  - 可以设置999999导致性能问题

建议修复:
  time_window_hours: int = Query(24, ge=1, le=2160)
