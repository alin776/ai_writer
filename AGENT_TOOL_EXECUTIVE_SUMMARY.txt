1. 从函数签名提取: 参数名、参数类型注解

  "parameters": {
    "type": "object",

关键问题: Schema只标记chapter_id为"string",没有UUID格式约束!

【发现3】ID来源问题 - 根本原因是提示词示例

问题现象:
- LLM生成简化ID: ch_1, ch_2
- 而非真实的UUID格式

根本原因:
1. 提示词示例不规范 (langgraph_agent.py:2766)
   示例: {"tool": "read_chapter_tool", "params": {"chapter_id": "abc-123-def"}}
          这个"abc-123-def"是简化格式,不是真实UUID

2. 设计上优先使用get_chapter_by_order_tool
   - 用户通常说"第3章"而不说"UUID xxx的章节"
   - get_chapter_by_order_tool(chapter_order: int)更易生成
   - read_chapter_tool是fallback,在已知UUID时才用

工具调用代码 (langgraph_agent.py:1642-1656):
- work_id来自state(用户上下文),不是LLM生成
- chapter_id优先使用LLM生成,fallback到state
- Fallback机制确保缺少正确ID时使用当前章节

【发现4】RAG检索返回真实UUID

位置: langgraph_agent.py (获取上下文工具, 663行)

RAG返回:
{
  "chapter_id": r['chapter_id'],  // <- 真实的UUID

重要: 
✓ RAG返回真实UUID
✓ 作为**上下文信息**返回给用户
✓ **不直接用于**后续的read_chapter_tool调用参数
✗ RAG结果不作为工具参数的来源

================================================================================
技术架构分析
================================================================================

工具绑定流程:
1. 定义工具 (@tool装饰器)
   └─ @tool async def read_chapter_tool(...)

2. 列出工具 (WRITING_TOOLS列表)
   └─ WRITING_TOOLS = [continue_writing_tool, ..., read_chapter_tool, ...]

3. 绑定到LLM (llm.bind_tools)
   └─ self.llm_with_tools = self.llm.bind_tools(WRITING_TOOLS)

4. 设置ToolNode (LangGraph workflow)
   └─ workflow.add_node("tools", ToolNode(WRITING_TOOLS))

5. 工具执行流程:
   user_input → AI决策(HTTPAIService)
     ↓
   生成JSON: {need_tools, tool_name, tool_args}
     ↓ (可能包含简化ID)
   参数标准化: _normalize_tool_params()
     ↓
   工具调用: read_chapter_tool.ainvoke({...})
     ↓ (自动fallback到state中的章节ID)
   返回结果: JSON章节信息
