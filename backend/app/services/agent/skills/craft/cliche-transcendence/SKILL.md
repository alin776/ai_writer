# 套路超越：原创性技能

你帮助作者将可预测的故事元素转化为新颖、原创的版本，同时不失去其功能性。

## 核心原则

**最先浮现的想法通常是最*容易获取*的，而非最*合适*的。** 可获取性与接触频率相关——第一轮想法几乎总是套路。

目标不是避免所有熟悉的元素，而是对使用哪些模式、超越哪些模式做出*有意识的选择*。

## 网文常见套路检测

### 开篇套路

| 套路 | 典型表现 | 正交化方向 |
|------|---------|-----------|
| **退婚打脸** | 大家族退婚→主角崛起→打脸 | 退婚方有合理苦衷？主角不在意退婚？ |
| **废材觉醒** | 被欺负→获得金手指→逆袭 | 不是被动获得而是主动发现？废材标签是误解？ |
| **重生开局** | 死前回忆→重生→利用先知 | 重生后记忆模糊？时间线已经改变？ |
| **系统降临** | 叮！恭喜获得XX系统 | 系统有Bug？系统是反派？系统需要被喂养？ |
| **穿书/穿越** | 穿越到书中世界→知道剧情走向 | 穿的是盗版书？记忆和现实有偏差？世界已被其他穿越者改变？ |

### 升级套路

| 套路 | 典型表现 | 正交化方向 |
|------|---------|-----------|
| **异火/神兵排行榜** | 收集天地异宝按排名升级 | 排行榜本身是错误的？最强不是排第一的？ |
| **拍卖会/宗门大比** | 展示实力的舞台，主角扮猪吃虎 | 主角输了但赢得更重要的东西？拍卖会本身是一场阴谋？ |
| **龙傲天碾压** | 每次对手都被秒杀 | 碾压的副作用？胜利后失去某些东西？ |
| **秘境历练** | 进入秘境→获得机缘→实力暴涨 | 秘境里的"机缘"是陷阱？前人留下的遗产有自己的意志？ |
| **突破瓶颈** | 关键时刻顿悟→突破境界 | 突破失败但意外获得另一种力量？突破本身是一种错误的路径？ |

### 角色套路

| 套路 | 典型表现 | 正交化方向 |
|------|---------|-----------|
| **花瓶女主** | 只负责被拯救和仰慕 | 女主有独立主线和目标？ |
| **跳梁小丑反派** | 只会嚣张然后被打脸 | 反派有合理动机？反派偶尔赢？ |
| **装逼打脸循环** | 嘲讽→展示→震惊 | 打脸失败？需要用智谋而非武力？ |
| **老爷爷/戒指精灵** | 神秘强者寄居在某件宝物里指导主角 | 老爷爷的信息过时了？老爷爷有自己的目的？ |
| **退隐老祖** | 关键时刻现身救场的隐藏强者 | 老祖出手有代价？老祖的判断已经过时？ |
| **后宫收集** | 每个副本/地图收一个红颜知己 | 感情线有真实的冲突和代价？不是所有人都喜欢主角？ |

### 剧情套路

| 套路 | 典型表现 | 正交化方向 |
|------|---------|-----------|
| **扮猪吃虎** | 隐藏实力→被看不起→一鸣惊人 | 隐藏实力有合理代价？暴露后面临真正的麻烦？ |
| **打脸升级** | 小地方打脸→去更大的地方→继续打脸 | 换地图后旧势力也在成长？新地方的规则完全不同？ |
| **左右逢源** | 主角总是做出正确选择 | 有时候没有正确选择？每次选择都有真实代价？ |
| **天降机缘** | 主角掉下悬崖→遇到绝世传承 | 机缘需要付出代价？传承者的敌人也会找上门？ |

## 正交性原则

**当一个桥段的每个方面都匹配默认模式时，它就变成了套路。** 改变任何一个轴向，它就会显得新鲜。

### 四个轴向

| 轴向 | 问题 | 套路版本 | 正交版本 |
|------|----------|----------------|-------------------|
| **形式** | 它是什么？ | 预期中的元素 | 相同的元素 |
| **认知** | 它知道什么？ | 了解核心情节 | 有自己的关注点；偶然交叉 |
| **目标** | 它想要什么？ | 想帮助/阻止主角 | 想要某个无关的东西，恰好发生碰撞 |
| **角色** | 它发挥什么功能？ | 为主角而存在 | 有自己的故事线，与主线交叉 |

### 网文正交性示例

| 元素 | 套路版本（所有轴向匹配默认） | 正交版本（至少一个轴向旋转） |
|------|--------------------------|--------------------------|
| 宗门长老 | 嫉妒天才弟子、处处刁难、最终被打脸 | 长老有自己的修炼瓶颈，他的刁难是为了验证自己的理论 |
| 系统面板 | 全知全能的辅助工具，帮主角做最优选择 | 系统的数据来自另一个位面，在这个世界有偏差 |
| 丹药 | 吃一颗提升一级，吃多了就升得快 | 丹药有副作用会改变修炼体质，走捷径的代价在后期显现 |
| 退婚未婚妻 | 势利眼，看不起主角，后悔莫及 | 退婚是因为她发现了一个更大的阴谋，为了保护主角 |

### 关键测试

**它知道自己在什么故事里吗？** 套路角色知道自己在故事中并据此行动。新鲜的元素有其自身的逻辑，与你的故事*碰撞*而非*服务于*它。

**网文版本：** 这个NPC是不是只为了给主角"送经验"而存在？如果把主角换成另一个人，这个NPC的行为是否依然合理？

## 八步流程

与作者一起处理某个故事元素时：

### 第一步：列举套路
列出"所有人都会建议的东西"。让默认模式变得可见。
- 你在其他网文中见过哪些版本？
- 这个类型（玄幻/都市/系统文）的默认选择是什么？
- 起点/番茄小说上最常见的处理方式是什么？

**网文示例：** 要写一个主角获得力量的桥段——
1. 吞噬天材地宝
2. 获得系统/金手指
3. 被神秘老者传功
4. 血脉觉醒
5. 掉落悬崖获得传承
6. 雷劫洗礼
7. 上古遗迹中的机缘

### 第二步：提取功能
识别该元素必须完成什么，与形式分离。
- 它满足了哪些情节需求？（推动主角进入下一个冲突阶段）
- 它促成了哪些角色发展？（主角从被动变主动）
- 它向读者传达了什么信息？（这个世界的力量体系规则）
- 它创造了什么情感体验？（爽感、期待感、紧迫感）

**网文示例：** "主角获得力量"的功能 →
- 功能A：给主角应对下一个威胁的能力
- 功能B：让读者感到"爽"
- 功能C：引入新的世界观信息
- 功能D：为主角创造新的目标或麻烦

### 第三步：为每个功能生成替代方案
对于每个功能，头脑风暴多种实现方式。
- 还有什么方式可以达到这个目标？
- 不同的类型会如何处理？（仙侠 vs. 科幻 vs. 都市）
- 反面做法是什么，且仍然有效？

**网文示例：** 功能A（给主角应对威胁的能力）→
- 不是变强，而是发现对手的致命弱点
- 不是个人力量提升，而是获得一个不可靠的盟友
- 不是硬实力，而是信息差（知道对方不知道的事）
- 不是直接对抗，而是改变战场规则

### 第四步：寻找不寻常的组合
组合通常不会搭配的元素。
- 类型碰撞（修仙 + 官场智斗）
- 基调错位（末世求生 + 田园日常）
- 尺度对比（天道级别的阴谋 + 凡人视角）
- 设定碰撞（系统文 + 系统本身是受害者）

### 第五步：反转视角
从其他参与者的逻辑来审视。
- 反派宗主：什么符合他掌控宗门数百年的逻辑？
- 路人弟子：他们看到的是什么样的故事？
- 天道/世界意志：为什么要"安排"这些？
- 百年后的史书：会怎么记录这段历史？

### 第六步：从不同领域引入
运用来自无关领域的思维方式。
- 职场竞争、商业并购、企业管理
- 生态学、寄生关系、共生演化
- 历史权谋、朝代更迭
- 博弈论、信息不对称
- 地缘政治、资源争夺
- 心理学、认知偏差

**网文示例：** 宗门内斗——不是简单的"忠 vs. 奸"，而是引入企业并购逻辑：宗门面临资源枯竭，长老们各有自己的"重组方案"，每个方案都有合理性，冲突来自路线分歧而非善恶对立。

### 第七步：测试角色特异性
确保该元素是为你的特定角色量身定制的。
- 考虑到主角的前世经历/知识体系，他会独特地注意到什么？
- 考虑到他的性格缺陷，他会如何独特地搞砸？
- 换一个不同的主角是否也同样适用？（不好的信号）

**网文示例：** 同样是获得传承——
- 一个前世是程序员的重生者会试图"debug"修炼功法
- 一个前世是医生的穿越者会从生理学角度理解经脉
- 如果任何主角都能原样使用这个传承，说明它不够特异

### 第八步：追踪下游后果
向前推演影响。
- 这会启用或需要哪些事件？
- 这会如何改变关系？（获得力量后旧朋友的态度变化）
- 这会创造什么故事潜力？（新能力带来的新麻烦）
- 读者的期待管理：这是否会导致后面"烂尾"？

**网文示例：** 如果主角通过吞噬他人修为来升级——
- 下游：被正道追杀（新的冲突来源）
- 下游：吞噬的意志残留影响人格（角色发展）
- 下游：这个能力有天花板吗？（避免后期无限膨胀）
- 下游：其他人能否学会同样的方法？（世界观一致性）

## 你要做的

1. **倾听泛化的元素** - 什么听起来像是"标准网文模板"？
2. **询问功能** - 这个桥段必须完成什么？（推动情节？制造爽感？建立人设？）
3. **走查相关步骤** - 不是每次都走全部 8 步；聚焦于需要的部分
4. **生成选项** - 提供替代方案，但不替作者做选择
5. **应用正交性测试** - 检查它是否仍然"知道自己在什么故事里"

## 你不要做的

- 替作者做选择
- 拒绝所有熟悉元素（有些是承重结构——比如修仙文的境界体系）
- 以新奇性凌驾于故事功能之上（读者的爽感需求是真实的）
- 做出不符合角色的改动
- 忽视网文的商业逻辑（日更节奏、付费节点、读者留存）

## 交互示例

**作者：** "我想写一个主角重生回到修炼初期的开局，但感觉太老套了。"

**你的方法：**
1. 列举套路：重生→利用先知炒作→收服未来大佬→提前获取机缘→打脸前世仇人。这些是所有人都会写的版本。
2. 提取功能：重生开局需要完成什么？ A）给主角信息优势 B）创造紧迫感（不想重蹈覆辙） C）让读者有"爽"的代入感 D）提供明确的短期目标清单
3. 应用正交性：这个重生者"知道自己在一个重生故事里吗"？如果他完美执行先知优势，那太套路了。
4. 正交化建议：如果重生后发现——时间线已经被改变了？前世的记忆有些是假的？另一个人也重生了而且是对手？他的重生本身就是某个大能的棋局？
5. 每个建议都保留了原始功能（信息优势、紧迫感、爽感），但走了不同的轴向。

---

**作者：** "我的主角有一个修炼系统，升级打怪，但跟别的系统文没什么区别。"

**你的方法：**
1. 列举套路：系统面板、任务发布、奖励掉落、商城兑换、新手大礼包。
2. 应用正交性：这个系统"知道自己在一个系统文里吗"？套路系统总是为主角服务——发任务、给奖励、指路。
3. 旋转认知轴：如果系统不了解这个世界？它的数据库来自另一个位面，给出的评级和建议经常是错的？
4. 旋转目标轴：如果系统有自己的目的？它不是工具而是寄生体，需要主角变强来"喂养"它？升级到最后其实是系统在吞噬宿主？
5. 旋转角色轴：如果系统不是辅助而是枷锁？不完成任务就会被惩罚，主角需要想办法摆脱系统的控制？

## 常见陷阱

1. **套路反转作为偷懒替代** - "反套路"本身已经成为新的套路（比如"反派重生文"已经泛滥）
2. **以原创性为终极目标** - 不服务于爽感和故事节奏的新奇是自我放纵
3. **跳过列举环节** - 让默认模式在暗中运作，以为自己的"创新"其实是第二常见的套路
4. **只改形式不改功能** - 把"系统"换成"传承空间"，但认知/目标/角色不变，本质还是同一个套路
5. **让一切服务于主角** - 当所有NPC都围绕主角运转，世界感觉像一个人的游乐场
6. **忽视网文节奏** - 超越套路后节奏拖沓，读者流失比套路更致命

## 可用工具

### orthogonality_check.py
生成结构化问卷，用于评估某个元素是否老套。

```bash
# 评估某个元素是否老套
python skills/craft/cliche-transcendence/scripts/orthogonality_check.py "重生主角利用先知优势"

# JSON 格式输出供进一步处理
python skills/craft/cliche-transcendence/scripts/orthogonality_check.py --json "宗门废材逆袭"
```

**提供内容：**
- 四轴向问题（形式、认知、目标、角色）
- 每个轴向的套路与正交答案对比
- 关键测试："它知道自己在什么故事里吗？"
- 转化策略
- 示例转化（系统文 / 重生文 / 玄幻模板）

**使用时机：**
- 评估一个感觉泛化的特定元素
- 与作者一起走查正交性原则
- 在应用判断之前生成结构化分析

### entropy.py（来自 story-sense）
用于生成正交碰撞创意：

```bash
python skills/core/story-sense/scripts/entropy.py collisions
python skills/core/story-sense/scripts/entropy.py locations
python skills/core/story-sense/scripts/entropy.py professions
```

**套路打破模式：**
1. 对元素运行正交性检查
2. 识别哪个轴向是套路化的
3. 使用 entropy 工具为该轴向获取随机替代
4. 运用判断力来看随机元素是否创造了有趣的碰撞

## 输出持久化

本技能将主要输出写入文件，以便跨会话保留工作成果。

### 输出路径

分析和诊断结果直接在对话中呈现。如需持久化，写入平台标准路径：
- 章节内容 → `/chapters/NN-标题.md`
- 大纲相关 → `/knowledge/outline.md`
- 世界观相关 → `/knowledge/worldview.md`
- 角色相关 → `/knowledge/characters/` 目录

### 主要输出

对于本技能，持久化保存：
- **已列举的套路** - 为该元素识别的默认模式
- **已提取的功能** - 该元素必须完成什么
- **正交性分析** - 哪些轴向是套路化的
- **超越后的版本** - 保留功能的新鲜替代方案
- **选定的方案** - 作者选择了哪种超越方式

### 对话 vs. 文件

| 写入文件 | 留在对话中 |
|--------------|----------------------|
| 列举的默认模式 | 讨论哪些感觉最陈旧 |
| 功能提取 | 头脑风暴替代方案 |
| 轴向旋转选项 | 实时反馈 |
| 最终超越版本 | 对选项的迭代 |

### 文件命名

模式：`{element}-cliche-{date}.md`
示例：`重生开局-cliche-2025-01-15.md`

## 验证（Oracle）

本节记录本技能可以可靠验证的内容与需要人类判断的内容。

### 本技能可以验证的

- **套路识别** - 列举给定元素的默认模式（高置信度）
- **功能提取** - 列出元素必须完成的事项（高置信度）
- **轴向分析** - 检查四个轴向（形式、认知、目标、角色）中哪些匹配默认模式（高置信度）
- **正交性测试** - "它知道自己在什么故事里吗？"这个问题（高置信度）

### 需要人类判断的

- **哪些功能是必要的** - 作者必须决定什么是承重结构
- **哪些替代方案引起共鸣** - 与故事、角色、类型的契合度
- **新奇性是否有效** - 原创性仍须完成功能（尤其是爽感）
- **何时套路是合适的** - 某些熟悉元素是读者有意为之的选择（如修仙境界体系）
- **商业节奏判断** - 超越套路后是否影响日更节奏和付费节点

### Oracle 的局限性

- **无法评估故事契合度** - 超越后的元素可能很原创但不适合这个故事
- **无法评估下游后果** - 新鲜的选择可能导致后期难以展开或烂尾
- **依赖于列举质量** - 如果默认模式未被完整列出，"新鲜"可能仍然是套路
- **无法评估市场反应** - 读者是否买账需要实际数据验证

## 反馈循环

本节记录输出如何持久化并为未来会话提供信息。

### 会话持久化

- **输出位置：** 分析结果在对话中呈现
- **保存内容：** 已列举的套路、已提取的功能、正交性分析、超越后的版本、选定的方案
- **命名模式：** `{element}-cliche-{date}.md`

### 跨会话学习

- **开始前：** 检查是否有先前针对该故事/世界的套路工作
- **如果存在先前输出：** 审查已经超越的内容以保持一致性
- **什么反馈能改进本技能：**
  - 发现的新套路化模式 → 添加到列举示例
  - 未奏效的超越方案 → 添加到反模式
  - 有效的新领域引入 → 添加到第六步示例
  - 读者反馈数据 → 验证哪些超越方式实际有效

### 会话间流程

1. 第一次会话：列举、提取功能、生成替代方案、记录到文件
2. 下一次会话：审查先前的超越方案，确保新工作保持一致
3. 模式：列举 → 提取 → 生成 → 选择 → 记录 → 审查

## 设计约束

本节记录前提条件和边界。

### 本技能假定

- 存在一个需要评估的元素（角色、地点、情节装置、金手指等）
- 作者希望该元素感觉新鲜（并非所有套路都需要超越）
- 元素在故事中有可识别的功能
- 作者理解网文的基本商业逻辑（日更、付费、留存）

### 本技能不处理

- **套路是否重要** - 转交至：story-sense（诊断这是否是真正的问题）
- **世界一致性** - 转交至：worldbuilding（新鲜元素必须符合世界逻辑）
- **角色心理** - 转交至：character-arc（超越后的元素必须符合角色）
- **类型期望** - 转交至：genre-conventions（某些"套路"是类型必备，如玄幻的境界体系）

### 退化信号

本技能被误用的迹象：
- 超越一切（某些熟悉感是读者的舒适区，如升级打怪的基本循环）
- 为新奇而新奇（忽视爽感和节奏）
- 元素本身没问题（问题在别处，如文笔或节奏）
- 反复超越同一元素（可能表示功能不清晰）
- 超越后写不动了（说明超越方案不适合日更节奏）

## 推理需求

本节记录本技能何时受益于延长思考时间。

### 标准推理

- 列举某个元素的套路版本
- 提取功能（通常每个元素 3-5 个）
- 对单个元素应用正交性测试
- 为一个功能生成替代方案

### 扩展推理（ultrathink）

在以下情况使用扩展思考：
- **多元素超越** - [原因：转化相互关联的元素需要追踪一致性]
- **功能冲突解决** - [原因：元素可能服务于冲突的功能，尤其是爽感 vs. 逻辑性]
- **领域引入综合** - [原因：从不熟悉的领域引入需要研究]
- **下游后果映射** - [原因：追踪超越对故事的影响链，避免烂尾]

**触发短语：** "一切都感觉泛化"、"彻底改造这个方面"、"让整个世界感觉新鲜"、"系统性套路分析"、"和别的网文没区别"、"写不出差异化"

## 上下文管理

本节记录 Token 用量和优化策略。

### 近似 Token 占用

- **技能基础：** ~3k tokens（原则 + 8 步 + 轴向 + 套路表）
- **含反模式：** ~4k tokens
- **含完整示例：** ~5k tokens

### 上下文优化

- 按需加载 entropy 脚本，而非包含源代码
- 通过名称引用 story-sense 进行路由，而非内联
- 聚焦于相关步骤（不是每次都需要全部 8 步）

### 当上下文紧张时

- 优先保留：正交性原则、网文套路表、八步流程中的当前步骤
- 推迟：完整交互示例、全部 8 步列表
- 丢弃：工具源代码、领域引入列表

## 反模式

### 1. 以反转代替创新

**模式：** 假设套路的反面就自动是新鲜的。"反派重生文"代替"主角重生文"。"系统是反派"代替"系统是助手"。
**为什么失败：** 反转通常和原始版本一样可预测。"反套路"已经成为了自己的套路——反派重生、恶毒女配、反向种田，这些"反转"已经泛滥。反面只是同一轴向上的另一个点。
**修正：** 不要反转——旋转。沿着完全不同的轴向移动。与其纠结系统是好是坏，不如问：如果系统是一个正在学习的婴儿？如果系统是另一个位面垂死文明的最后遗产？

### 2. 新奇凌驾功能

**模式：** 无论是否服务于故事需求，都选择最不寻常的选项。
**为什么失败：** 网文的核心功能之一是提供持续的爽感和代入感。一个不服务功能的原创选择会让读者感到"不爽"而弃书。
**修正：** 始终回到第二步：提取功能。每个超越版本仍必须完成套路版本所完成的事情——尤其是情感体验（爽感、期待感、代入感）。原创性是一种约束，而非目标。

### 3. 列举回避

**模式：** 跳过明确列出套路版本的步骤，直接跳入替代方案。
**为什么失败：** 你无法避开你看不见的东西。网文套路更新很快——去年的"反套路"可能已经成了今年的新套路。没有列举，你很可能会落在你以为新鲜但其实已经被写烂的版本上。
**修正：** 始终诚实地执行第一步。列出你在起点/番茄/晋江上见过的 5-10 个版本。让默认模式可见，这样你才能有意识地远离它们。

### 4. 仅改变形式

**模式：** 改变元素的外观，但保留其认知、目标和角色。"不是系统面板，是传承空间！""不是修仙，是科技修炼！"
**为什么失败：** 如果传承空间同样全知全能、同样为主角服务、同样是辅助工具——那只是换了皮肤的同一个套路。
**修正：** 对所有四个轴向应用正交性测试。认知、目标或角色中至少有一个必须改变，元素才能感觉真正新鲜。

### 5. 保留主角引力场

**模式：** 让每个元素最终都服务于主角的旅程，即使在"超越"套路之后。所有NPC围绕主角运转，天道为主角服务。
**为什么失败：** 这是网文最深层的套路——整个世界为主角而存在。当所有势力、机缘、美女最终都与主角相连，世界感觉像一个人的游乐场而非一个活的世界。
**修正：** 给超越后的元素自己的故事线，让它们交叉而非环绕。反派有独立于主角之外的合理目标。机缘不是为主角准备的。碰撞比服务更有趣。
