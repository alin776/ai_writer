# 数据库迁移指南（团队协作必读）

## 🎯 适用场景

**其他开发者** 拉取代码后，需要同步数据库结构

---

## ✅ 方案1：使用 Alembic 迁移（推荐）

### 步骤1：拉取最新代码
```bash
git pull
```

### 步骤2：激活虚拟环境
```bash
# Windows
cd backend
.\venv\Scripts\activate

# Linux/Mac
cd backend
source venv/bin/activate
```

### 步骤3：安装依赖（首次）
```bash
pip install -r requirements.txt
```

### 步骤4：配置环境变量
复制 `.env.example` 为 `.env`，填入数据库连接信息：
```bash
DATABASE_URL=postgresql+asyncpg://用户名:密码@localhost:5432/数据库名
SECRET_KEY=your-secret-key
OPENAI_API_KEY=your-api-key
```

### 步骤5：检查数据库迁移状态
```bash
alembic current
```

输出示例：
```
c02326821f1e (head)  # 你的当前版本
```

### 步骤6：执行待执行的迁移
```bash
alembic upgrade head
```

输出示例：
```
INFO  [alembic.runtime.migration] Running upgrade c02326821f1e -> dfef30e5f344
INFO  [alembic.runtime.migration] Running upgrade dfef30e5f344 -> 73bf53905445
INFO  [alembic.runtime.migration] Running upgrade 73bf53905445 -> add_ai_guidelines_001
```

### 步骤7：验证迁移成功
```bash
alembic current
```

应该输出：
```
add_ai_guidelines_001 (head)
```

## ⚠️ 方案2：使用 init_db() 自动创建（不推荐）

**注意**：此方法不推荐用于团队协作，仅适用于快速开发测试。

### 如何使用？
直接启动服务器，`init_db()` 会自动创建所有表：
```bash
python -m uvicorn app.main:app --reload
```

### 问题
1. ❌ 表已存在时会跳过创建（看起来正常，但实际上数据库可能不同步）
2. ❌ 无法追踪数据库结构变化历史
3. ❌ 无法回滚到之前版本
4. ❌ 团队成员的数据库可能不一致

---

## 🔧 常见问题排查

### 问题1：迁移时报错"表已存在"
```
sqlalchemy.exc.ProgrammingError: 关系 "ai_guidelines" 已经存在
```

**原因**：表已通过 `init_db()` 创建，但 alembic 不知道

**解决**：手动标记迁移为已执行
```bash
alembic stamp head
```

### 问题2：不知道当前数据库版本
```bash
alembic current
alembic history
```

### 问题3：需要回滚到之前版本
```bash
# 回滚到上一个版本
alembic downgrade -1

# 回滚到指定版本
alembic downgrade 73bf53905445

# 回滚到初始状态
alembic downgrade base
```

### 问题4：数据库连接失败
检查 `.env` 文件中的 `DATABASE_URL` 配置：
```bash
# 格式
postgresql+asyncpg://用户名:密码@主机:端口/数据库名

# 示例
postgresql+asyncpg://postgres:123456@localhost:5432/novelaide
```

## 🚀 快速命令参考

```bash
# 查看当前版本
alembic current

# 查看迁移历史
alembic history

# 升级到最新版本
alembic upgrade head

# 降级到上一个版本
alembic downgrade -1

# 查看待执行的迁移
alembic heads

# 手动标记版本（表已存在时使用）

```

## 👥 团队协作最佳实践

### 开发者职责
1. ✅ 创建新模型后，**立即**生成并执行迁移
2. ✅ 提交代码时，**务必包含**迁移脚本
3. ✅ Pull代码后，**立即执行** `alembic upgrade head`
4. ✅ 遇到问题，**先查看**迁移历史和当前版本

### 禁止操作
- ❌ 不要手动修改数据库表结构
- ❌ 不要删除或修改已提交的迁移脚本
- ❌ 不要直接使用 `Base.metadata.create_all()` 在生产环境
- ❌ 不要绕过迁移系统直接创建表
