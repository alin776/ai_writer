# 小说分析性能压测指南

## 📋 测试目标

验证小说分析系统在长文本场景下的性能表现，确保：
1. **稳定性**：20章+作品能够稳定完成分析
2. **性能**：单章分析时间在合理范围内

4. **超时保护**：超长分析不会无限等待

## 🔧 配置调优

### 1. 超时配置

文件：`backend/app/core/config.py`

```python
# AI调用超时（单次请求）
OPENAI_TIMEOUT: int = 120  # 秒，默认2分钟

# 整体分析超时（完整流程）
ANALYSIS_TIMEOUT: int = 3600  # 秒，默认1小时
```

**调整建议**：
- 如果遇到频繁超时：增加 `OPENAI_TIMEOUT` 到 180 或 240
- 如果100章+作品：增加 `ANALYSIS_TIMEOUT` 到 7200（2小时）

### 2. 重试配置

```python
# 单章分析失败最大重试次数
ANALYSIS_MAX_RETRIES: int = 3  # 第1次 + 2次重试

# 重试延迟
ANALYSIS_RETRY_DELAY: int = 2  # 秒
```

**调整建议**：
- 如果AI服务不稳定：增加 `ANALYSIS_MAX_RETRIES` 到 5
- 如果遇到限流：增加 `ANALYSIS_RETRY_DELAY` 到 5 或 10

### 3. 前端轮询配置

文件：`src/components/editor/NovelAnalysisPanel.tsx`

```typescript
const maxAttempts = 240; // 240次 * 5秒 = 20分钟
```

**调整建议**：
- 如果长文本作品：增加到 360（30分钟）
- 如果网络延迟高：增加轮询间隔到 10秒

## 🐛 常见问题

### Q1: 压测卡在某一章不动

**可能原因**：
- AI服务响应慢
- 章节内容过长
- Token超出限制

**解决方案**：
1. 检查后端日志，找到卡住的章节
2. 检查该章节字数（建议单章 <20000字）
3. 增加 `OPENAI_TIMEOUT` 配置
4. 检查AI服务状态

### Q2: 大量章节分析失败

**可能原因**：
- API Key 余额不足
- API 限流
- 提示词配置错误

**解决方案**：
1. 检查 `.env` 中的 `OPENAI_API_KEY`
2. 检查API余额和限流策略
3. 检查 `backend/app/services/ai/prompts/novel_analysis.json`
4. 增加重试次数和延迟

### Q3: 前端显示超时但后端还在运行

**可能原因**：
- 前端轮询上限过低
- 后端分析确实很慢

**解决方案**：
1. 增加前端 `maxAttempts` 配置
2. 优化后端分析性能（减少prompt长度）
3. 使用更快的AI模型

## 📈 性能优化建议

### 1. 短期优化（已实现）

- ✅ 添加超时配置（防止无限等待）
- ✅ 添加重试机制（提高成功率）
- ✅ 添加性能监控（日志记录耗时）
- ✅ 前端轮询优化（进度停滞检测）

### 2. 中期优化（建议）

- ⏳ 并发分析（同时分析多章，需注意API限流）
- ⏳ 章节分片（超长章节分段分析）
- ⏳ 结果缓存（避免重复分析相同内容）
- ⏳ 使用更快的模型（如 gpt-3.5-turbo）

### 3. 长期优化（规划）

- 📝 分布式分析（使用Celery任务队列）
- 📝 GPU加速（本地Embedding模型）
- 📝 智能预分析（提前判断章节难度）
- 📝 流式分析（边分析边存储）
